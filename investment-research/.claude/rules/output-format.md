# 输出格式

本项目产出两类文档：**分析报告**（`analysis/` 下六份中间产物）和**投资研报**（`output/` 下最终交付物）。这份规则定它们的骨架和提交要求。

**Markdown 的限制只到「文稿层」。** 分析报告、研报正文、附录说明，一律用 Markdown 纯文本起草，不引入 docx / xlsx 这类二进制文稿格式。但**量化模型不受这条限制** —— 模型输入、假设、计算程序、生成结果可以且应当用结构化格式（YAML / JSON / CSV）与 Python 程序承载，见 `model/README.md`。**把这句话读成「连模型也只能写成 Markdown 表格」，等于要求人手工维护一张会算错的表。**

---

## 一、提交规范（CFA 投资分析比赛校赛硬性要求）

这一节是外部规则，不能商量，逐条照做：

| 项 | 要求 |
| --- | --- |
| 语言 | 正文全英文 |
| 格式 | PDF，A4 纵向 |
| 正文篇幅 | ≤ 10 页 |
| 附录篇幅 | ≤ 10 页 |
| 边距 | 16–18 mm（默认 17 mm） |
| 正文字号 | 10–10.5 pt |
| 来源 / 脚注字号 | 8–9 pt |
| 页码 | 每页标明 |
| 封面 / 封底 | 统一用 CFA 协会规定模板，**不计入正文**。**官方只提供前封面**（可编辑 Word 版已落在 `templates/cover/cover-official.docx`），**未提供封底模板** |
| AI 使用 | 正文中必须注明（见第五节） |
| 引用来源 | 研报与路演 PPT 内均须注明 |
| 引用体例 | **须用通行引用体例** —— 官方明文举例 Chicago、Harvard、MLA（规则原文出现三次）。自订的 `(Source: …)` 括注**不算体例**，只能当补充，见 §2.3 |
| 计算底稿 | 务必保留，以备检查 |

**边距与字号是默认值，不是硬规定。** 拿到官方排版要求后，**官方要求覆盖默认值** —— 以官方为准，同时更新本表。目前的默认值是按「A4 纵向、正文 10 页装得下」反推的常见取值，用于试排阶段的起点。

**本项目在 Markdown 里写文稿、由脚本导 PDF**，套 CFA 封面封底、排页码、控页数由脚本与人工配合完成。转换路线与工具见 §1.4。

### 1.1 中英文分工

| 文档 | 语言 | 说明 |
| --- | --- | --- |
| `analysis/` 六份中间报告 | 中文 | 工作稿，供自己审阅核对 |
| `output/investment-report.md` | 英文 | 提交件，逐句对应 PDF |

中间报告是工作稿，不是提交件，不受「全英文」约束。定稿时由 report-writer 译成英文并组装。

### 1.2 日期与期限（四个独立字段，不许合并）

日期混用是这类报告最隐蔽的错 —— 看着都对，算出来差一大截。**下面四个日期各记各的，任何一处写「数据截至 X 日」而没说清是哪一个，都算没写。**

| 字段 | 是什么 | 初值 |
| --- | --- | --- |
| **信息截止时间** | 本轮检索到的最新信息的时点（新闻、公告采到哪一天） | 单独记录，与行情日分开 |
| **行情日期** | 现价、市值取自哪一天的收盘 | 2026-09-18 |
| **估值基准日** | 折现的起算时点、股数与净借款对齐的时点 | 2026-09-18 |
| **目标日期** | 目标价对应的未来时点 | 行情日期 + 12 个月 |

**目标期限统一为 12 个月。** 报告里写 `12-month horizon`，不再出现 6 个月、18 个月这类别的期限 —— 期限不同，目标价不可比。

**提交截止：2026-10-08 中午 12:00**（校赛说明原文：「需在 2026 年 10 月 8 日中午 12:00 之前将完整的全英文研究报告及相关附件资料提交到指定链接」）。据此倒排试排与定稿时间。

**行情日期遇休市的处理：** 若目标日期或基准日当天休市，**行情取此前最近的一个交易日，并保留该实际交易日日期** —— 写成 `as of 2026-09-18（实际交易日 2026-09-17）` 这种形式。**不许把非交易日的日期标成行情来源日。**

### 1.3 试排（不能等最后）

**不要等写满 10 页才第一次碰 PDF。** Markdown 里看着正常的表格，导成 A4 后经常出问题 —— 列宽溢出、中文断行、来源括注把行撑开、页码错乱、附录被挤到第 11 页。这些留到定稿才发现，返工的是整份文档。

**初稿出来后先试排 2~3 页**（取抬头 + 表格最多的那一两节），验证五件事：

| 验证项 | 看什么 |
| --- | --- |
| 表格 | 最宽的那张（估值汇总 / 可比公司 / 计算底稿）有没有溢出页宽或被截断 |
| 来源标注 | 括号里的 `(Source: 2025 Annual Report, p. 12)` 会不会把行撑开、换行后还读不读得通 |
| 页码 | 正文每页标了没有；**封面封底有没有被误计入页码**（封面之后正文应从 1 起排） |
| 图片 | 图有没有被排到版心外；横图按版心宽度缩、竖图按版心高度缩，都不能变形、不能出血 |
| 附录 | 计算底稿的表格跨页后表头是否重复、正文引用能不能对上 |

**这五项由 `tools/pdf/check_layout.py` 自动查**，`build.ps1` 出片后默认就跑。封面封底不计页码，用 `--cover-pages` / `--back-cover-pages` 告诉它各有几页。

**试排结果要记下来** —— 用的什么工具、哪几项通过、哪几项要调整。它决定后面所有内容的写法。带着未解决的版式问题继续堆内容，等于把返工量往后滚。

**占位内容必须一眼可辨。** 试排和早期的样张里，凡是还没有真实数据的格，一律写成 `[[待填]]` 这种带双方括号的显式标记，**不许填 0、不许填一个看起来合理的数、不许把状态行预填成「已确认」**。标记要短 —— 占位符本身不能是可断行的长英文单词，否则在窄表格里会撑破右边距（`[[待填]]` 实测可断，长英文标记不可断）。需要补充说明时，把说明写在标记**后面**，不要塞进标记里。占位符混进定稿、或者占位符被填成了一个没人审过的数，是这份报告最难查的一类错 —— 因为它读起来跟真数据没区别。

### 1.4 PDF 转换路线（本机实测可用）

**已在本机验证的路线**（2026-09-19 实测，改动前先复核）：

| 组件 | 本机状态 |
| --- | --- |
| pandoc 3.10 | 可用 |
| MiKTeX（xelatex） | 可用，中文字体 `Microsoft YaHei` 正常 |
| Python 3.14 + pdfplumber | 可用（版式检查，见 `tools/pdf/check_layout.py`） |
| Microsoft Edge | 可用（备选：HTML → 无头打印成 PDF） |

**主路线：Markdown → pandoc → xelatex → PDF。入口是 `tools/pdf/build.ps1`，不要手敲 pandoc。**

```powershell
cd investment-research
.\tools\pdf\build.ps1 -InputPath output\investment-report.md
```

产物落在 `build/`（不入库），出片后自动跑版式检查；要跳过加 `-SkipCheck`。

路线由四个文件撑起来，**改之前先读 `tools/pdf/README.md`**：

| 文件 | 管什么 |
| --- | --- |
| `tools/pdf/build.ps1` | 构建入口：路径、调 pandoc、跑检查 |
| `tools/pdf/header.tex` | 导言区：字体、断行、表格、图片、页码、封面封底环境 |
| `tools/pdf/divs-to-latex.lua` | 把 `::: {.cover}` 这类围栏 div 转成 LaTeX 环境 |
| `tools/pdf/check_layout.py` | 版式检查：页数、溢出、页码、内容、图片 |

**四条硬约束**（都实测踩过，改路线前必须知道）：

- **A4 纵向是 pandoc 默认**，不必显式指定；`geometry:margin` 控制边距
- **`fontsize` 只接受 10pt / 11pt / 12pt**，要落在 10–10.5 pt 就用 `10pt`；需要 10.5 pt 时在 `header.tex` 里用 `\fontsize` 覆盖
- **字体只在 `header.tex` 一处设**，不要另外传 `-V CJKmainfont` —— pandoc 管不到 sans 与 mono，两处各设一半必然对不上
- **`divs-to-latex.lua` 不是可选项**：pandoc 对围栏 div 是**静默丢壳**，去掉这个过滤器，封面不分页、来源与占位块样式全部失效，而且**编译不报错**

**宽表溢出**：pandoc 默认把 Markdown 表转成 `longtable`，超过页宽时编辑器只看到列多、看不到溢出，靠 `check_layout.py` 报出来；解决办法是拆表，别靠缩字号硬塞。

**备选路线：Markdown → HTML → Edge 无头打印。** 版式控制更细（CSS `@page` 直接写 A4 和边距），但需要自己写 CSS。主路线跑不通时再换。

**两条路线都要留一个可复现的命令**，写在 `tools/` 的说明里 —— 换一台机器、换一个时间，要能用同一条命令跑出同一个结果。

### 1.5 封面与封底（封面已到，封底官方没有）

**封面封底用 CFA 协会规定模板，不计入正文、不计页码。**

**封面已到（2026-09-19）** —— 官方发的是 **Word 可编辑版**，落在 `templates/cover/cover-official.docx`，来源与可填字段见同目录 `来源.md`。只有高亮处（队名、赛区名、Disclosures 三个 `[...]`）可填，**其余内容含 CFA 标志一字不得改**。

**封底没有官方模板。** 规则正文通篇只写 `the front cover page provided by CFA Institute`，Appendix C 也只给前封面。校赛说明要求「封面和封底」，CFA 这一侧没有 —— **须向赛区主办方确认「封底」指什么，确认前不要自己造一个**。

**封面自带 Disclosures 五项**（Ownership and material conflicts of interest / Receipt of compensation / Position as an officer or director / Marketing making / Disclaimer），与项目自拟的 AI 辅助声明（第六节）**不是一回事，两者都要有，不互相替代**。

拿到模板后要做一次**核验**：逐项核对可填字段填全没有，结论记进 `model/verification/`。

**不许自己画一个「看起来像」的封面当作定稿** —— 封面是赛事方给的，自造的一旦被核对就是版式不合规。

**视觉风格与论点结构可以参考外部优秀作品，但只借这两样。** 版式规则、页数上限、章节结构一律以官方规则为准 —— 参考作品用了几页、怎么配色，都不是我们能改规则的理由。

## 二、成品骨架（output/investment-report.md）

章节按赛事给出的顺序与名称组织。**本项目约定：标题照抄，不合并、不调序、不缺节。** 这是**项目自我约束，不是赛事原文的规定** —— 手上的规则文本列了这几节、并要求「内容包括但不限于」，但**没有写明「标题不得改名」**。将来拿到官方规则或与评委确认可调时，以官方为准并更新这一句。

增补小节是允许的（原文写「包括但不限于」）。某节确实没内容 → 保留标题，正文写 `No content available.` + 原因。

```
【封面】CFA 协会规定模板 —— 不计入正文、不计页码

【正文第 1 页开头 —— 七项必填信息】
【免责声明】

① Business Description
② Industry Overview and Competitive Positioning
③ Investment Summary
④ Valuation
⑤ Financial Analysis
⑥ Investment Risks
⑦ Environmental, Social, and Governance

References
AI Usage Disclosure
Appendices（数据来源清单 + 计算底稿）

【封底】CFA 协会规定模板 —— 不计入正文、不计页码
```

**⑦ 用名已定：`Environmental, Social, and Governance`（ESG）。** 校赛说明写「公司治理」，官方规则与评分表写 `Environmental, Social, and Governance`（15 分）；官方规则第 4 节另规定学校自评时**必须按 Appendix D 打分**，而 Appendix D 那一节就叫 `Environmental, Social, and Governance`。**评分用名是 ESG，故取官方用名。** 三块都要有实质内容，治理是其中 G 的核心块。证据见 `reference/README.md`。

**上面那套方括号是骨架示意，落到 Markdown 里用的是围栏 div。** 四种类名，写了才有对应排版：

| 写法 | 排版效果 |
| --- | --- |
| `::: {.cover}` … `:::` | 封面：单独一页、**不出页码**，之后页码重置为 1 |
| `::: {.backcover}` … `:::` | 封底：单独一页、**不出页码**，不重置页码 |
| `::: {.source}` … `:::` | 来源标注：8–9 pt |
| `::: {.placeholder}` … `:::` | 占位内容：一眼可辨，不伪装成真数 |

```markdown
::: {.cover}
[[待填]] —— CFA 官方封面模板待替换
:::

（正文第 1 页开头七项 + 免责声明，然后 ① ~ ⑦、References、Appendices）

::: {.backcover}
[[待填]] —— CFA 官方封底模板待替换
:::
```

**封面必须是文档的第一个元素。** `cover` 靠分页起新页：封面之前若还有内容，
那段会被推成单独一页**并带上页码**，封面反而没页码 —— 页码整体错位一格。实测踩过。

**漏写外壳的后果是静默的**：pandoc 对围栏 div 只丢壳、留内容，编译不报错，
但样式全不生效。所以「看着像正常的 Markdown」不代表排出来是对的。

### 2.1 正文第 1 页开头的七项（必填，缺一不可）

固定七行，照这个格式填：

```
Company:         {公司全称（英文）}
Exchange:        {交易所全称，如 Shenzhen Stock Exchange (SZSE)}
Ticker:          {股票代码，如 300308.SZ}
Sector/Industry: {GICS 板块} / {所在行业（英文）}
Recommendation:  {BUY / HOLD / SELL}
Current Price:   CNY {现价} (as of {YYYY-MM-DD})
Target Price:    CNY {目标价} ({±XX.X%})
```

四处容易漏，单独点出来：

- **`Sector/Industry` 一项要填两个值** —— GICS 板块（如 `Information Technology`）与行业（如 `Communications Equipment`）。规则 PDF 第 16 页把两词合写为**一项**，Appendix A 单行本又把它们**拆成两项**；写成 `Sector/Industry: A / B` 同时满足两种读法。**只写 `Industry` 会把 Sector 丢掉。**
- 现价**必须注明日期**，写法是 `as of 2026-09-18` 这种
- 目标价**必须给出相对现价的涨跌百分比**，如 `(+28.40%)`
- 投资建议**只用 BUY / HOLD / SELL 三个词**，不用 Overweight、Outperform 这类档位

这七项漏任何一项直接算缺项，和后面的章节平级重要。

### 2.2 页数配比（正文 10 页封顶）

| 节 | 页数 |
| --- | --- |
| 第 1 页抬头 + Investment Summary | 1.00 |
| Business Description | 0.75 |
| Industry Overview and Competitive Positioning | 1.25 |
| Valuation | 2.25 |
| Financial Analysis | 1.25 |
| Investment Risks | 1.25 |
| Environmental, Social, and Governance | 1.25 |
| References | 0.50 |
| Data / AI disclosure | 0.50 |
| **合计** | **10.00** |

配比是给撰写时的收敛目标，不是硬切。某节写超了，**从 Investment Summary 里省** —— 那节最容易写水。

**Valuation 那 2.25 页是唯一不能动的一节。** FCFE 逐年预测（两条路径 + 差异桥）、可比对照、FCFF 核验、反向估值、两组敏感性表的底稿都要落在这一节或附录里，压缩它等于把校赛明文要求的底稿挤掉。要腾地方，从 Investment Summary 和 References 里腾。

**Data / AI disclosure 那 0.50 页是独立一行，不是 References 的附属。** 官方 Appendix B 的四条要求（Acknowledge / Verify / Evaluate / Reflect）要在这半页里写全 —— 见第五节。**它放正文还是放附录，官方规则没有明文，见 §2.6。**

### 2.3 引用与底稿

- **References 一节必须是通行引用体例** —— Harvard 作者-年份 / Chicago / MLA 任选一套，全篇统一。官方规则原文出现三次：「Sourced information should be properly cited using a generally accepted citation system」，明文举例 Chicago Manual of Style、Harvard、MLA。**条目要给全**：作者或机构、标题、出版者、日期、URL 或页码
- 正文每个数字后面标来源，格式见 `.claude/rules/data-standard.md` §1.1，用英文写，如 `(Source: 2025 Annual Report, p. 12)` —— **这是补充标注，替代不了 References 里的正式条目**。只写括注、不给参考文献表，不符合官方的「通行引用体例」要求
- 附录里放**数据来源清单**（逐条列，带来源类型与三个属性）和**计算底稿**（估值模型的每一步中间量）
- 计算底稿是校赛明文要求保留的东西，不能只给最终结果
- **估值数字只有一个源**：**统一模型**（`model/`）算出来的结果文件。正文、图表、抬头目标价、附录底稿里的每一个估值数字都从它引用，**不另行计算、不手工誊抄** —— 同一个数在两处各算一遍迟早分叉
- **`analysis/valuation.md` 里的模型工作表由脚本生成，不手工维护。** 人手工维护一张几十行的表，迟早会出现「正文用了新版、表里还是旧版」。生成命令与目录约定见 `model/README.md`
- 估值报告输出前要做**独立复算**：换一条路径重算 FCFE / Ke / 终值 / 三情景，与模型结果逐行对表。**对不上就是有错**，先查再改
- **模型结果只有 `approved` 且版本一致的才准进成品。** 门禁规则见 §2.5

**来源等级不等于模型正确。** `Grade A` 只说明数字从哪来（公司自己披露的原文），**不说明模型对不对**。A 级输入配错的折现率、错的口径、错的期间，结论一样是错的。模型正确性靠的是口径核验、现金流与折现率匹配、以及上面那次独立复算 —— 这三样都没有的时候，别拿「来源是 A 级」当结论可靠的证据。

### 2.5 状态标记与输出门禁

**每个产出的数字都带状态，成品只准引用 `approved` 的。** 光靠「记得别用旧的」不够 —— 旧数字在文件里躺着，谁引用的时候都不会收到提示。所以状态要**机器可读**。

**状态取值（写在文件的 YAML 状态块里）：**

| 状态 | 含义 | 成品能不能引用 |
| --- | --- | --- |
| `approved` | 分析师已确认，且版本与当前假设版本一致 | **可以** |
| `candidate` | 候选，尚未确认 | **不可以** |
| `deprecated` | 已作废（方法被推翻、指标被删除、假设被替换） | **不可以** |
| `superseded` | 被更新版本取代 | 仅当指向的新版本是 `approved` |

**状态块的写法**（放文件最顶部，用 YAML 围栏，让脚本和人一眼都能读）：

```yaml
status: deprecated
version: v-legacy-2026-09-18
reason: 旧方法（三法加权合成），WACC 用负净债务作债务权重
deprecated_on: 2026-09-18
superseded_by: model/results/valuation.json
deprecated_values: [790.26, -11.80%, 2033.13]
```

**`deprecated_values` 是门禁真正用来拦人的字段** —— 列出这批作废结果里**不允许再出现在成品中**的数字（逗号分隔）。光写 `reason` 只是给人看的，脚本读不到具体是哪几个数。**别把它写成描述**，写要拦的那些值本身。

**作废可以只针对一部分。** 整个文件被推翻就整份标 `deprecated`；只是其中某个指标作废（例如 `financial.md` 里被删除的「信心度」），同样标 `status: deprecated`，但在 `reason` 里写明**作废范围只到哪**，其余内容照旧有效 —— 状态块里不设「部分作废」这种取值，机器只认那四个状态。

**已作废产出的处理：**

- `analysis/valuation.md`（整份作废）与 `analysis/financial.md`（仅「信心度」作废）已在文件顶部各标一个 `status: deprecated` 状态块，自带的 `deprecated_values` 就是门禁的拦截清单
- **正文原样保留**，不删不重写 —— 校赛要求保留计算底稿，且删掉就看不出改过什么
- **任何下游文件引用到已作废数字，一律算错误**，不是「不太严谨」

**输出前的门禁检查（必须跑）：**

1. 扫 `analysis/` 与 `output/`，看有没有引用 `deprecated` / `candidate` 状态的数字
2. 核对成品里每一个估值数字的版本号，与当前 `approved` 假设版本是否一致
3. 拦截三类东西进成品：**旧目标价、旧评分（含已删除的信心度）、未经确认的预测假设**

检查脚本见 `tools/model/gates.py`，用法与输出格式见 `model/README.md`。**检查没过，不导出 PDF。**

### 2.6 References 与 AI 披露放正文还是附录（**规则无明文，维持正文**）

**先把规则依据记下来，不自行假设。** 已核对的官方规则原文（`reference/cfa-rules/CFA-RC-官方规则-2026-2027赛季.pdf`）里：

| 规则说了什么 | 规则**没有**说什么 |
| --- | --- |
| 正文 ≤ 10 页 A4，**不含 CFA 协会提供的前封面**（Appendix A） | **没有**说明 References 属于正文还是附录 |
| 附录 ≤ 10 页 A4 | **没有**说明 AI 使用披露属于正文还是附录 |
| 必含七节（原文注明「包括但不限于」） | **没有**给 References 或 AI 披露指定位置 |
| 「Sourced information should be properly cited using a generally accepted citation system」 | 只要求**引用了就要标**，没要求标在哪一页 |

**结论：把 References 与 AI 披露放进附录，在现有规则文本里找不到依据。**

**本项目的处置 —— 维持正文，按 §2.2 的配比各占 0.50 页。** 理由：

1. **规则没授权就不动。** 挪进附录看起来省了 1.00 页正文，但那是在规则沉默处做对自己有利的解释 —— 一旦评委按「附录不算正文、必含内容应在正文」来读，省下的这页会把整份报告的可信度赔进去。
2. **§2.2 的 10.00 页配比已经把这两项算进正文**，总数正好封顶，没有超页压力。
3. **AI 披露尤其不适合放附录。** 官方规则注明「评委很可能会就报告里任何重要数据与结论追问 AI 的使用方式」—— 放在正文里、和结论同一本册子，比藏在附录更符合「如实披露」的要求。

**要改这条，需先满足下面任一条件**，并在此处记录依据：

- 拿到赛事方或赛区主办方的书面答复，明确 References / AI 披露可放附录
- 官方发布新版规则，明文指定这两项的位置

**在那之前，不自行假设、不为了腾页数把它们挪走。** 页数不够从 Investment Summary 里省。

### 2.4 结论措辞

**评级**用 BUY / HOLD / SELL 三档，不用 Overweight、Outperform 这类自造档位，也不用「暂不形成评级」这类自造状态。

**评级只有一个来源 —— `Valuation` 一节。** 财务分析、行业分析里的「看多 / 看空」是**对经营与行业事实的分类**，不是买 / 持 / 卖的建议：一家公司经营质量再好，价格透支了也不该买；经营平平但价格足够低，也可能值得买。把这些信号直接当评级用，等于把「公司好不好」和「股票值不值得买」混成一件事。**结论摘要里引用财务或行业信号时，要写明这是经营质量判断，不构成方向性依据。**

**不给精确到小数点的「信心度」。** 三个子分析里两个看多一个中性，本来就只是「多数偏正面」这么一件粗事；换算成 `66.67%` 是凭空多出两位有效数字，读者会当成「有 66.67% 的把握」。**一致程度用定性词**（一致 / 基本一致 / 有分歧 / 方向相反），可计算的只有**数据完整度**（指标取到了多少）。

**主估值与对照方法的分歧诊断不清时，评级落 HOLD**，并在同一页显式写明：`因主估值与对照方法的分歧未能解释，本次评级不构成方向性判断。`只写 HOLD 不写这句披露，等于把分歧藏起来。

**目标价（Target Price）**：校赛抬头要求填**一个**目标价并给出相对现价的涨跌百分比，所以这里给基准值；支撑它的**估值区间**写在 Valuation 一节里，说明区间对应的方法和关键假设。两个都要有 —— 抬头给点值方便评委一眼看到，正文给区间体现审慎。

**目标价必须从基准日内在价值桥接出来**，不能把基准日折现值直接改个标签当目标价。桥接要走过时间推移带来的折现推进、期间股利分配、股本与资本结构变化，每一步在 Valuation 一节里写出来。三个价格（基准日内在价值 / 12 个月目标价 / 买入安全边际价格）各是什么就说是什么，**不得把打过折的价格叫作内在价值**。

**投资期限**：统一写 **`12-month horizon`**，与 §1.2 的「目标日期 = 行情日期 + 12 个月」对齐。不写 6 个月、18 个月这类别的期限 —— 期限不同，目标价不可比。

**假设未经确认，不得产出正式估值、评级与目标价。** 这条管的是**输出**，不是计算 —— 审批前允许算历史指标、核口径、搭模型、跑合成数据测试（见 `valuation` 技能 §四），但不许把这些结果包装成正式结论对外。**技术上的「算得出来」和流程上的「可以说」是两件事。**

**结论定稿必须经分析师确认** —— 这是「人在回路」第 4 个节点（结论措辞审查）。AI 不得自行定稿评级和目标价，也不得替分析师在确认记录里签名。

### 3.1 六份的分工

每份中间报告对应成果报告的一节，**一一对应，不交叉**：

| 中间报告 | 对应成品章节 | 分析什么 | 主要数据来源 |
| --- | --- | --- | --- |
| `analysis/business.md` | ① Business Description | 公司概况与沿革、产品与服务、收入构成、客户与供应商集中度、管理层与股权结构、发展战略 | `raw_data/earnings/` + 公司公告 |
| `analysis/industry.md` | ② Industry Overview and Competitive Positioning | 行业规模与增速、竞争格局、市场份额、竞争优势、Porter 五力、行业趋势 | `raw_data/reports/` + `raw_data/news/` |

| `analysis/risks.md` | ⑥ Investment Risks | 公司特有风险、行业与宏观风险，按影响程度排序；**风险情景**（触发条件 → 改变的假设 → 对每股价值的影响）。**流程：候选假设阶段先出定性风险 → 确认后由统一模型算情景 → `risk-analyst` 核查风险是否已进模型 → 成文**。撰写方只呈现，不建数字 | 五份分析报告提炼 + `model/results/` 的情景结果 + 财报风险提示章节 |


指不回任何一份中间报告的说法，**删掉**，不要保留。

## 四、图表标准

本项目以文字和表格为主，**不自动生成图片**。分工：

- **表格是主力**，绝大多数对比都用表（见 4.1）
- **图只在表格表达不了时才用**：走势形状、结构占比、空间关系。图由**使用者**按定稿数据自行绘制后放进 `figures/`，命名、格式与引用方式见 `figures/README.md`
- **项目里的程序只产出数字与表格，不产图** —— 需要图形化时，文稿只说明该画什么，不假装自己画得出

### 4.1 用表格的场合

- 多期数据对比（≥3 期）
- 关键比率表
- 可比公司对照
- 估值敏感性分析（FCFE 驱动假设双变量，如终值增长率 × 股权成本）
- 风险清单、数据来源清单

表格规范：

- 第一列是指标名，后面按时间从新到旧排列
- 表头写清楚单位（如「营业收入（亿元）」/ `Revenue (CNY mn)`）
- 表格**下方一行**统一标注数据来源与口径
- 缺失值写「未披露」，待核实写 `[待核实]`，不适用写「—」，**不留空格**

### 4.2 用列表的场合

- 并列的观点（用 bullet）
- 有先后顺序的步骤（用编号列表）
- 因果链条（用 `A → B → C` 单行表示）

### 4.3 不用图的场合

趋势描述用「指标 + 数值序列」的文字表达：

```
营业收入：2023 年 107.18 亿元 → 2024 年 238.60 亿元 → 2025 年 400.00 亿元，连续三年增长
```

需要图形化时，说明这是留给使用者自己画。**本项目不产出图片文件** —— 研报要配图，由使用者按定稿数据绘制后放进 `figures/`，再在文稿里用 `![](figures/xxx.png)` 引用。图片会被自动限制在版心内，不会冲出页面，但**一张横图就吃掉小半页**，配图前先算页数。

## 五、AI 使用披露

校赛明文要求：**报告中使用了 AI 工具必须注明**。本项目整条流水线由 AI 驱动，所以这一节不能省。

**官方 Appendix B 给了四条要求**（Acknowledge / Verify / Evaluate / Reflect），本节按这四条组织。官方另注明：**评委很可能会就报告里任何重要数据与结论追问 AI 的用法，队伍要准备现场解释**（规则 PDF 第 17 页）。

在 References 之前或之后单设一节，用英文写，四条逐条回应：

1. **Acknowledge —— 用了什么**：哪些 AI 工具、怎么用、为什么用。如 `This report was produced with the assistance of an AI research pipeline (Claude Code).`
2. **Verify —— 怎么核的**：输出有没有对照可信来源交叉核验，说明**共识程度**（几路来源一致）。对应 `data-standard.md` 的「交叉核验」字段
3. **Evaluate —— 怎么判的**：查偏倚与遗漏、有无别的视角、数据来源的规模与严谨度，说明对各输出的**信心与风险**。**现行版本没有这条**
4. **Reflect —— 怎么影响判断的**：AI 工具与输出**如何影响了团队的判断**，其**强项与弱点**各是什么。**现行版本没有这条**

写法要**如实**。少报或含糊（如只写「辅助写作」）一旦被问起，比多报危险得多 —— 评委大概率会当场追问。
