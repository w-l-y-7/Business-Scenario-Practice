# report-digest：研报观点整合

把手上几份券商研报（或它们的转述）拢到一张对照表里，落成 `raw_data/reports/` 下的一个文件。

**产出是原材料的二次整理，不是结论。** 研报是**别人的观点**，你的活儿是把它记准、记全、把分歧摆出来 —— 不替它背书，也不替它下判断。下游 company-analyst 和 report-writer 都建在这份文件上。

## 速查表

| 场景 | 怎么处理 |
| --- | --- |
| 同一篇研报被多家转载 | 只留**最原始**的那家，不重复建档 |
| 目标价分歧 ≥ 20% | 标 `[分歧显著]`，列出各家数值 |
| 评级不一致 | 单列一张评级对照表 |
| 发布日期超过 180 天 | 标 `[过期]`；超过 12 个月直接标 `[时效性不成立]` |
| 盈利预测数字 | 标「（预测值）」，**绝不与实测数混列** |
| 拿不到研报原文 | 可用转述，但降级标注 + 写明只到标题级 |
| 研报未署名机构 | 标 `[待核实]`，**不作为论证依据** |

## 一、动手前先定三件事

1. **标的** —— 公司名称 + 证券代码
2. **要整合的研报** —— 几份、哪几家、什么时段
3. **输入形态** —— 研报原文，还是二手转述

**有几份做几份**，不因为凑不够 3 份就不干活。覆盖面不足写进「数据缺口」节，别硬凑数也别沉默。

## 二、先判输入是几手材料

同 `earnings-extract` 的原则：原文优先，拿不到可退转述，但**降级标注 + 在缺口节写明未取得原文**；不编链接。

研报本身是 **B 级**（专业机构产出，有署名有依据）。转述研报观点的财经媒体是 **C 级**。

**最容易踩的坑：标题级概括不是摘要。** 如果检索工具只返回标题和链接、没返回正文，那你写进「核心观点」列的只是**标题的复述**，不是研报观点。这种情况必须在「采集说明」里明写：

> 检索工具只返回标题与链接，**未返回研报正文**。本文件的核心观点**仅为标题级概括**，不是研报摘要；盈利预测数字、估值方法、关键假设一概未取得。

不写这句，下游会以为读到了研报全文，拿标题级概括去做估值分析 —— 这是本技能最严重的失败模式。

## 三、逐份提取七个字段

| 字段 | 说明 | 注意 |
| --- | --- | --- |
| 券商名称 | 研报出具机构 | 未署名的写「未标明机构」+ `[待核实]`，**不得作为论证依据** |
| 发布日期 | 研报发布日，**不是转载日** | 超 180 天标 `[过期]`；超 12 个月标 `[时效性不成立]`；拿不到写 `[待核实]` |
| 投资评级 | 买入 / 增持 / 中性 / 减持 | 标是**首次覆盖**还是**维持** |
| 目标价 | 12 个月目标价 | **必须与估值方法一起记** —— 只有目标价、没有推导过程，下游没法复现 |
| 核心观点 | 3-5 条关键判断，每条 ≤ 50 字 | 概括，不是抄写；抓结论不抓论据堆砌 |
| 盈利预测 | 未来 1-3 年营收、净利润 | 标「（预测值）」 |
| 主要风险 | 研报提及的核心风险 | 照记，**不替它补充**它没说过的风险 |

评级用标准档位，不替研报自造词。研报用了非标准表述（如「强烈推荐」）就照录原词，并在备注里注明。

## 四、分歧检测

### 4.1 目标价分歧

取各家目标价的**最高值与最低值**算偏差：

```
最大偏差 = (最高目标价 − 最低目标价) / 最低目标价
```

≥ 20% → 标 `[分歧显著]`。

**只有 1 家给目标价时不存在分歧** —— 别硬算，注明「仅 1 家给出目标价，无法计算分歧」。这一点在缺口节也要提，因为它意味着「市场一致预期」根本不成立。

### 4.2 评级对照

评级不一致时单列一张表：

| 评级 | 家数 | 机构 |
| --- | --- | --- |

### 4.3 现价与隐含空间

目标价脱离现价没法解读 —— 31 元的目标价，现价 20 元和现价 35 元是两个完全不同的故事。所以要记**比较基准日的收盘价**：

```
隐含涨跌幅 = (目标价 − 现价) / 现价
```

**现价的来源标成「行情数据（来源：Wind / 同花顺等，日期）」**，不要标成研报 —— 标错了下游会以为股价是从研报里读的。拿不到现价就写「需外部行情数据」，**不要硬凑**。

## 五、数字格式

照 `data-standard.md` §三：金额亿元 2 位小数、比率和增速百分数 2 位小数、倍数 2 位小数、日期 YYYY-MM-DD。

两条额外要求：

- **预测值与实测值必须分开**。研报的盈利预测是估算，要么标「（预测值）」，要么单独成表，**不与其他实测数字混在同一列**。
- **目标价的币种和单位写清楚**（`31.20 元`），别只写 `31.2`。

## 六、提不到的数怎么标

| 情况 | 怎么写 |
| --- | --- |
| 来源说不清是谁发的、什么时候发的 | `[待核实]` + 说明卡在哪 |
| 来源里有，但取决于版本/口径 | 写数值 + `[待核实：口径]` + 说清疑问点 |
| 来源里确实没有这项 | 「未披露」 |
| 该对比不适用 | 「—」 |
| 需要估算 | `[估算]` + 方法与依据，**不与其他实测数字混列** |

**四条禁止**：不编数、不用记忆里的数、不拿估算冒充实测、不因为「这里应该有个数」就补一个。

**特别提醒**：研报的目标价、评级、日期这三项最容易记混或记串。同一家机构两次评级的两个目标价，**不要合成一个**，分两行记并标 `[待核实]` 说明可能是同一次评级的重复转述。`[待核实]` 的项最后汇总成一节。

## 八、交棒

写完汇报四件事：**整合了几份研报、覆盖区间、缺什么、有几条 `[待核实]`**，并说明文件落在哪、分歧检测的结论是什么。

然后**停下**。数据源确认是项目 `CLAUDE.md` 第五节的第 1 个「人在回路」节点，必须等分析师确认数据是否齐全、是否可靠，才轮到下游接棒。

## 必须遵守的规则

1. **不编数、不编目标价、不编日期、不编机构名**。说不清的一律标 `[待核实]`。
2. **只在 `raw_data/reports/` 下写入**，不碰 `analysis/`、`output/` 和 `raw_data/` 的其他子目录。
3. **不替研报背书，也不替它下判断**。研报说买入，你记「买入（首次覆盖）」；至于对不对，那是分析师的事，不在这一棒。
4. **标题级概括必须声明**。只拿到标题就老实写「不是研报摘要」，伪装成摘要比拿不到材料危害更大。
5. **不越人在回路节点**。整合完即停，等第 1 个节点确认。
