# valuation：估值分析

读 `raw_data/earnings/` 的财报数据加市场数据，估内在价值，产出 `analysis/valuation.md`，对应 CFA 研报第 ④ 节 Valuation。

**FCFE 模型是比赛硬性要求，无论数据是否顺手都必须做这一路。** 缺关键输入时照 §三 写明卡在哪、怎么降级，但**不许省掉这一节跳到别的路**。评委按有没有 FCFE 这一节打分。

**这不是「三个方法投票」，是「一个主估值加两个对照」。** FCFE 出结论，前瞻可比和 FCFF 只用来检验它、质疑它、解释它。三路不做加权平均 —— FCFF 与 FCFE 同属折现法、在企业价值层面高度相关，把它们加权等于对同一件事重复计权。

**估值是最容易编数的地方，因为假设多、又都能算得出来。** 增长率、折现率、周转、融资安排、终值假设、情景概率全是假设 —— 每一项都要能指回依据，指不回去的标 `[估算]` 并列进「关键假设」表，等分析师确认。**宁可输出「数据不足以估值」，也不要拿一堆估算值凑一个看起来很确定的结论。**

## 速查表

**四段走，顺序不能倒** —— 研究证据 → 候选假设 → 团队确认 → 正式计算。

| 阶段 | 做什么 | 卡点 |
| --- | --- | --- |
| **一、研究证据** | 1 基准日与口径核验（§二）；2 数据门槛检查（§三）；3 搭统一模型骨架并跑合成数据自测（§4.1） | 股本、归属、净借款三项没核完，不进下一步；缺关键输入的标「降级使用」，不硬填估算值 |
| **二、候选假设** | 4 列关键假设表（§4.2），逐项标来源或 `[估算]`；5 识别定性风险交 `risk-analyst` | 每项都要能指回依据，指不回的标 `[估算]`；**未确认的假设不得用于输出正式估值** |
| **三、团队确认** | 6 把候选假设交分析师审查，填确认记录（§4.3） | **人在回路第 2 个节点。** 确认记录含真实确认人、日期、假设版本；**不得预填为已确认** |
| **四、正式计算** | 7 逐年预测与情景终值；8 敏感性（§五）；9 前瞻可比 + FCFF 交叉检验；10 三个价格（§六）；11 独立复算（§八） | 终值 `g < Ke`；三路不合成；**输出一律由统一模型生成**（§4.1） |
| **收尾** | 12 分歧诊断与评级（§七）；13 输出门禁检查（§八） | 诊断不清 → HOLD + 显式披露；门禁不过 → 不导出 |

### 审批前能做什么、不能做什么

这一条容易走极端 —— 要么「什么都没确认所以什么都别动」，要么「先算一版看看再说」。都不对。

| | 审批前 | 依据 |
| --- | --- | --- |
| ✅ **可以** | 历史指标计算、口径核验、模型搭建、**合成数据测试**、敏感性方法验证 | 这些不依赖预测假设，或者用的是假数据 |
| ❌ **不可以** | 用未经确认的预测假设输出**正式估值、评级、目标价** | 这是对外结论，假设没定就没有依据 |

**关键区别是「预测假设」和「对外输出」。** 拿历史数据算历史 FCFE、把模型程序搭起来、用一组标着 `SYNTHETIC` 的假数据跑通全部计算路径 —— 这些都是准备工作，不但允许，而且**应该尽早做**，否则等假设确认了才发现程序跑不通，返工更贵。

反过来，只要你的输入里含**未确认的预测假设**（收入增速、利润率路径、终值 g、可比集合），产出的数字就**只能留在内部当草稿**，不能写进报告、不能进摘要、不能当评级依据。

**先算一版再回头补假设，仍然是本技能最容易犯的错。** 那样做等于把结论当成既定事实去凑假设。区别在于：用假数据练手不算错，用真假设先算出结论再让分析师「确认」算错。

`gap = (隐含每股价值 − 基准日收盘价) / 基准日收盘价`。收盘价取**基准日**数值并标注日期。

## 一、动手前先定三件事

1. **标的与四个日期** —— 估值必须挂在一个具体日期上（股价每天都在变）。四个日期分开记、不许合并：
   - **信息截止时间**（检索到哪一天）、**行情日期**（现价取自哪天）、**估值基准日**（折现起算、股数与净借款对齐）、**目标日期**（= 行情日期 + 12 个月）
   - 遇休市 → 行情取此前最近交易日，**保留实际交易日日期**
   - 详见 `output-format.md` §1.2
2. **模型归属口径** —— 归母还是合并，从第一步就定死，全模型一致（见 §二）
3. **数据可得性** —— 先通读 `raw_data/earnings/`，逐项核对要的输入有没有

## 二、基准日与口径核验（第一步，不能跳）

这一节查的是**报告里最容易被顺手带过、又最伤结论的三件事**。三项没核完，不要开始算。

### 2.1 股本与基准日对齐

估值挂的日期是**基准日**，但财报给的是**报告期末**。两者之间公司可能已经发行、回购、归属激励或转增股本。

- 股数取**基准日**口径，不直接拿最近一期财报的期末股本
- 核对基准日前发生的发行、回购、股权激励归属、转增、可转债转股等重大资本事项
- **融资现金与股数同步处理** —— 只更新其中一个会让每股价值和股权价值对不上

股数变了，每股价值、市值、全部倍数分母跟着变。这项错了，后面算得再准也没用。

### 2.2 利润与现金流的归属必须一致

用**归母净利润**去配合并范围的折旧摊销、CapEx、营运资本变动，会把少数股东对应的那部分现金流混进来，算出来的 FCFE 不是股东的现金流。

- 全模型统一用一个归属口径，并在报告里写明
- 选归母口径 → 折旧、CapEx、ΔWC 也要按归属比例调整，或说明少数股东占比小到可忽略及依据
- 选合并口径 → 净利润也要用含少数股东的口径

**混搭不报错，只会悄悄算错。** 报告里必须有一句话交代这件事。

### 2.3 净借款不等于债务余额变化

`净借款 = 有息负债期末 − 有息负债期初` 只是个近似。债务余额的变化里可能还藏着汇率折算、非现金租赁增加、并购并入、科目重分类。

- **优先取现金流量表的项目**：「取得借款收到的现金」减「偿还债务支付的现金」，必要时加回租赁负债的本金偿付
- 拿不到现金流项目、只能用余额倒算时，**写清这是代理口径**，并把能识别的差额逐项说明
- 有外币债务的，把汇率折算的影响单独指出 —— 它不进 FCFE，那不是融资活动带来的股东现金流
- **拿不到融资数据也不许默默按 0 处理** —— 按 0 等于假设公司永不加杠杆，是个藏起来的强假设。要么写清取数路径，要么明说这一项降级处理及其影响

## 三、数据门槛检查（第二步）

先逐项核对输入，缺什么写什么。**门槛检查的结果要写进报告（§4.1），让分析师一眼看出这次估值建立在什么证据上。**

| 方法 | 关键输入 | 缺了怎么办 |
| --- | --- | --- |
| **FCFE（主）** | 净利润、折旧摊销、资本支出、营运资本变动明细、净借款（或融资现金流）、Ke 组件（无风险利率、beta、股权风险溢价）、**可分年的经营预测基础**（收入、利润率、周转） | 缺 Ke 任一组件 → 标「无法执行」；缺可分年预测基础 → 退回单期，写明这是降级使用 |
| 前瞻可比（检验） | 核心可比公司的**前瞻** P/E（或 EV/EBITDA）与预测年度、目标公司对应指标 | 无前瞻数据 → 退回 TTM 倍数，标「口径不同步」，并说明这会削弱交叉检验的效力 |
| FCFF（核验） | FCFF 的推导过程（从净利润或经营现金流）、WACC 全组件、逐年预测 | 缺 WACC 任一组件 → 标「无法执行」，只用另两路 |

**三条旧禁令已经取消，改成下面的处理方式：**

- **基期现金流为负** → 仍然可以做。但必须说明**转正路径**：靠什么转正、需要多少外部融资、经营能否自我维持。负现金流本身不是不能估值，是**不能装作它不重要**。
- **基期净利润为负** → 不禁止。按未来现金流与融资条件判断，并说明亏损是周期性的还是结构性的。
- **算出的价值 ≤ 0 或显著异常** → **先查模型**（口径、单位、折现率、终值），再检查是否存在融资缺口或困境情景。不要直接把它当「无效」丢掉 —— 悄悄扔掉最悲观的那一路，结论会系统性偏乐观。

## 四、统一模型、候选假设与团队确认

**这一节排在正式计算之前。** 研究证据（§二、§三）先读完，把假设列出来，确认了才进 §五。

### 4.1 统一模型（程序与目录）

**估值不是一张手工维护的 Markdown 表，是一段能重跑的程序。** 手工表的毛病是固定的：改了假设忘记改下游、正文引的是旧版、两个人各算一份对不上。**把所有量化收进一个程序，这些问题一次性消失。**

**目录约定**（五类东西分开存，各自职责清楚）：

| 目录 | 放什么 | 谁写 |
| --- | --- | --- |
| `model/inputs/` | **历史输入** —— 从 `raw_data/` 整理出的结构化财务数据 | 分析师，超出范围要找 `data-collector` |
| `model/assumptions/` | **候选假设**（`candidate.yaml`）与**已确认假设**（`approved.yaml`，含确认记录） | 候选由计算方写；已确认必须由分析师填 |
| `model/results/` | **生成结果** —— 机器可读结果 + 渲染好的 Markdown 表 | **只由程序写，不许手工改** |
| `model/verification/` | **核验记录** —— 勾稽、口径、`Ke > g`、复算的检查输出 | 程序生成，人复核签字 |

**计算程序放 `tools/model/`**，与 `tools/` 下其他脚本一致。

**模型必须覆盖的模块**（缺一块就不算「统一」）：

| 模块 | 内容 |
| --- | --- |
| 收入驱动 | **产品收入 = 销量 × ASP**（或按业务线拆），不用一个总数乘以增长率 |
| 利润表 | 毛利（收入 − 成本）、期间费用、净利润 |
| 营运资本 | 存货、应收、应付与周转天数（DIO / DSO / DPO），ΔWC |
| 资本开支与折旧 | CapEx 节奏、折旧摊销政策，两者分别建模 |
| 债务与现金 | 有息债务、货币资金、净借款、利息 |
| 股本 | 基准日股数，含发行 / 回购 / 激励归属 |
| FCFE | 主估值，逐年预测到每股价值 |
| FCFF | 一致性核验（WACC 口径） |
| 远期可比 | 交叉检验（前瞻倍数） |

**历史输入的边界：** `model/inputs/` 里的每一个数都要能追回 `raw_data/` 的具体文件与页码。整理时把来源一起写进结构里，**不把 `raw_data/` 的原始值抄成一份没有出处的副本**。

**缺失数据不得默认为零。** 这条由程序强制：任何必需输入缺失时**报错并列出缺哪几项，不许静默按 0 参与计算**。「按 0 处理」会悄悄把一个缺失变成一个强假设（比如「公司永不加杠杆」），而且算出来的结果看起来完全正常。确实要按某个值处理时，必须**显式写进假设表并标注依据**。

所有假设集中成一张表：

| --- | --- | --- | --- |
| 销量 / ASP 假设（分产品线） | | | |
| 收入增速（分期） | | | |
| 毛利率路径 | | | |
| 期间费用率 | | | |
| 折旧摊销政策 | | | |
| 资本支出节奏 | | | |
| 存货 / 应收 / 应付周转天数（DIO / DSO / DPO） | | | |

| Ke 各组件（无风险利率 / beta / 股权风险溢价） | | | |

| 情景概率 | | | |

有来源的标来源（`（来源：中金，《XX 深度》，2026-08-15，B 级）`），没来源的标 `[估算]` 并说明是依什么判断的。

**三行不设默认值** —— 情景概率、任何形式的估值权重、安全边际折价。**空着就是空着**：

- **情景概率**：不预先配置。三情景并列报出，不给加权点值。要报概率就必须有依据，没依据就不报
- **估值权重**：本项目不做加权合成（§五），所以没有权重这一项
- **安全边际折价**：可选的买入门槛，由分析师定，**不设默认比例**。不设就只报内在价值与目标价

**这批假设就是「人在回路」第 2 个节点（核心假设审查）的审查对象** —— 逐年预测、终值假设、可比集合都在里面。

**候选假设阶段同时做一件事：识别定性风险。** 列假设的过程里就能看出哪几项最容易出事（毛利率假设偏乐观、客户集中度相关的收入假设没有缓冲）。把这些**定性风险**整理出来交 `risk-analyst` —— 定量情景要等假设确认后由统一模型算（见 `risks` 技能 §5）。

### 4.3 确认记录（不得预填）

假设确认后，在 `model/assumptions/approved.yaml` 里写确认记录。**四个字段缺一不可：**

| 字段 | 要求 |
| --- | --- |
| `confirmed_by` | **真实确认人** —— 具体是谁 |
| `confirmed_on` | **确认日期**，YYYY-MM-DD |
| `assumption_version` | **假设版本号**，与模型结果版本一致 |
| `scope` | 确认的范围（全部假设 / 仅某几项） |

**不许预填。** 新建的 `approved.yaml` 是**空模板**：`confirmed_by` 为空、`status: unapproved`。**AI 不得替分析师签名，不得把状态预先写成 `approved`，不得填一个占位的确认人。**

- **确认前不用于输出**：未确认的假设可以拿去搭模型、跑合成数据，但**产出的数字不得作为正式估值、评级或目标价输出**（见速查表「审批前能做什么」）
- **不先算一版「参考值」垫着** —— 那版数字会变成锚，讨论就变成在锚上修修补补
- **确认过程里假设被改动 → 按新假设从零重算**，不保留旧数字
- 假设版本与模型结果版本**必须一致** —— 任何一处改动，两处版本号同时更新；版本不一致的结果不得进成品

## 五、估值方法

### 5.1 FCFE —— 主估值

**FCFE 算的是股东能拿到的现金流，用股权成本 Ke 折现。**

```
FCFE = 净利润 + 折旧摊销 − 资本支出 − 营运资本变动 + 净借款
```

#### 逐年预测，不是拿基期套增长率

**不能以某期 FCFE 为起点、直接套 35%/15%/3% 这类固定增长率。** 那样做等于把基期的备货、扩产、偿债状态原样延续到未来 —— 基期在囤货、在扩产、在还债，模型就假设它永远在囤货扩产还债。

要逐年预测经营本身，再落到现金流。**收入从业务驱动量出发，不从「一个总数乘增长率」出发：**

| 年份 | 销量 | ASP | 收入 | 毛利 | 期间费用 | 净利润 | 折旧摊销 | CapEx | 营运资本 | ΔWC | 净借款 | **FCFE** |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

多产品线就按线拆开再合计。**用销量 × ASP 而不是直接乘总增速，是为了让假设能被业务事实检验** —— 「出货量受产能限制只能增 30%」是可验证的判断，「收入增速 35%」不是。

每一列都要有驱动假设：销量与 ASP 路径、毛利率、费用率、折旧政策、扩产节奏、存货与应收应付周转天数、融资安排。**这些假设在 §4.2 已确认过才用得上** —— 这里只是把它们落到逐年数字上，不产生新假设。中途发现假设表缺项 → 退回 §4.2 补确认，不在这里就地拍一个。

**这张表由 `tools/model/` 生成，不在报告里手工填。**

预测年份按业务周期定（通常 5 年，扩产周期长的可到 7~10 年），并在报告里说明为什么取这个年数。

#### 备货要建两个分支

存货大幅上升时，未来有两种走法，**两种都要建模，不能预先选一种**：

- **释放分支** —— 备货对应订单落地，未来收入上来、营运资本回吐现金，FCFE 转好
- **减值分支** —— 需求不及预期，存货计提跌价，未来利润与现金流同时受损

只算其中一种，等于把最大的不确定性替读者做了决定。

#### 情景

悲观 / 基准 / 乐观三档，**三档的数值全部列出来**，不能只给一个数。

**不默认配置情景概率。** 如果报概率，必须写明依据（历史频率 / 行业先例 / 分析师判断），没依据的标 `[估算]` 或**干脆不报概率** —— 报三个情景的每股价值，让读者自己看区间，好过编三个加起来等于 100% 的数。**没有概率就不给加权期望值**，也别把三档「平均一下」当基准。

#### 敏感性

**必做两组，一组资本成本、一组经营：**

| 组 | 变量 | 回答什么问题 |
| --- | --- | --- |
| **资本成本** | Ke × 终值增长率 `g` | 折现假设变一点，结论翻不翻转（校赛常规要求） |
| **经营** | **毛利率 × DIO（存货周转天数）** | 经营假设变一点，结论翻不翻转 —— 对制造业和项目型公司，这组往往比第一组更关键 |

再按公司特点补：Ke 各组件（尤其 beta）、CapEx 节奏、ASP 或销量。

**敏感性不是装饰，是替代原来那两个百分比指标的。** 报告里要能回答「哪个假设变动会翻转方向」。**两组都要出双变量表**，存在 `model/results/`，正文引用生成结果，不手工画。

**预留给后续、暂时不实现的分析：**

- **反向估值求根** —— 给定当前股价，反解出市场隐含的增长率或毛利率。用途是回答「现价隐含了什么假设」，比正向估值的说服力强，但需要先有稳定的正向模型
- **券商预测差异归因** —— 把自家预测与券商一致预期逐项拆开（收入差多少、利润率差多少），定位分歧出在哪个假设上

**这两项标注为「预留」，不写成已完成。** 预留的意思是接口和数据位留好，等正向模型跑通后再接。

#### 终值

```
终值 = FCFE_n × (1 + g) ÷ (Ke − g)
```

- **`g` 按公司成熟阶段、币种和稳定期再投资能力设定**，不再一律取 `min(盈利增速, 3%)`。成熟期公司的 `g` 可以贴近长期通胀，高成长期公司要在过渡期内把增速降下来
- **必须保证 `g < Ke`** —— 否则终值公式失效，算出来是负的或无穷大。设定后先自查这一步
- **终值占比要报出来**（终值现值 ÷ 股权价值）。占比过高说明结论主要由一个远期假设驱动，必须在报告里点明
- 稳定期的再投资要与增长匹配（`g` 高就要有对应的资本支出），不能只调增长不管投入

#### 敏感性

至少做这几项：Ke 各组件（尤其 beta）、终值增长率、营运资本周转、CapEx 节奏。**敏感性不是装饰，是替代原来那两个百分比指标的。** 报告里要能回答「哪个假设变动会翻转方向」。

### 5.2 前瞻可比 —— 交叉检验

**它的任务是检验主估值，不是另出一个结论。** 最后要回答的是「市场给同类业务什么价，我的主估值站不站得住」。

- **核心可比按业务重合度选** —— 选与标的做同一门生意、同一批客户、同一类产品的公司。业务结构明显不同的（上游器件商、综合业务集团）放进**参考组**，仅供对照，**不进中位数**
- **不为凑数纳入弱可比** —— 三家真可比好过五家凑数的。可比公司不足就从简，并说明局限
- **统一预测年度和利润口径** —— 我方的预测年度与可比的预测年度要同期，利润口径（归母 / 扣非 / 摊薄）要一致。**优先用前瞻倍数**；只有 TTM 数据时退回 TTM，并标明「口径不同步」
- **解释差异** —— 逐家说明与标的在增长、盈利质量、客户结构、风险上的差异，以及这些差异对倍数意味着什么
- **折价只在有依据时施加** —— 无固定比例。认为标的流动性或规模确实劣于可比，才按差异大小定折价，并把依据写进假设表。没有依据就不加折价
- **禁止跨倍数比较** —— EV/EBITDA 与 P/E 分子分母都不同，**不能直接比数值大小**来判断哪边便宜。要比较就用同一倍数横向比

### 5.3 FCFF —— 一致性核验

**FCFF 折的是归属全体资本提供者的现金流，用 WACC 折现，得到企业价值，再桥接到股权价值。**

#### 现金流与折现率必须匹配

- **FCFF 配 WACC**，**FCFE 配 Ke**。用 WACC 折 FCFE（或反过来）是最常见的硬伤，口径不匹配会系统性偏高或偏低
- 明确写出 **DCF 是折现法的总类** —— FCFF 折现和 FCFE 折现都属于它，不是并列的两种方法

#### WACC 用有息债务的市场价值

```
WACC = E/(E+D) × Ke + D/(E+D) × Kd × (1 − T)
```

**这里的 D 是有息债务的市场价值，不是净债务。** 现金不是负债务 —— 把「有息负债 − 货币资金」当 D，会算出超过 100% 的股权权重和负的债务权重，公式形式就失真了。

- `E` 取基准日市值，`D` 取有息债务市值（账面值可作近似时说明）
- **现金及非经营性资产在桥接环节处理**，不进权重
- 现金与有息债务都要取**基准日**口径，与 §2.1 的股数对齐

#### FCFF 的来源要交代清楚

不能直接拿「经营活动现金流净额 − 资本支出」当 FCFF 用。必须先勾稽：

- 这是**从净利润推导**还是**从经营现金流推导**？走了哪些调整？
- **利息支付的现金流分类** —— 计入经营活动还是筹资活动？分错会让经营现金流里混着属于债权人的现金流
- **税盾**怎么处理的？利息的抵税效应是否已在税前利润与税率中体现，避免重复计税
- **非经营性项目**（投资收益、公允价值变动、资产处置、政府补助、其他非流动资产）剔除了没有？

勾稽过程和每一笔调整，都要留在底稿里。

#### 桥接到股权价值

```
企业价值 − 净债务 = 股权价值
净债务 = 有息债务 − 现金及非经营性资产
```

**加回或扣减了什么，逐项列出。** 长期应付款这类性质不明的科目，明确写出是否计入及理由。

#### 它和 FCFE 同族

FCFF 与 FCFE 在**企业价值层面高度相关**。两路方向一致**不构成两次独立验证** —— 报告里必须点明，别让读者以为「两个方法都指向同一结论」是互相印证。

**FCFF 的用途是核验：** 它与主估值差多少、差异来自哪里（资本结构、税率、非经营性项目口径）。解释得清就用它佐证，解释不清就如实写「两路未能调和」。

## 六、三个价格，分开写

这三个数回答不同问题，**不能只写一个再换个标签**：

| 价格 | 是什么 | 怎么来 |
| --- | --- | --- |
| **基准日内在价值** | 按基准日信息，公司值多少 | 主估值（FCFE）三情景的区间 |
| **12 个月目标价** | 一年后股价的预期水平 | 从基准日内在价值**桥接**：加上时间推移带来的折现推进，减去期间分配的股利，加上或减去资本结构变化 |
| **买入安全边际价格** | 什么价位买才留有余地 | `内在价值 × (1 − 门槛比例)`，门槛是可选的决策标准 |

**12 个月目标价的桥接不能省。** 把基准日折现值直接标成「12 个月目标价」，等于假设一年内什么都没发生 —— 折现率推进了一整年，期间还可能有分红和股本变化。桥接的每一步都要写出来。

**安全边际是决策门槛，不是估值方法。** 它回答「什么价格值得买」，不改变公司值多少。**禁止把打了折的价格叫作「内在价值」** —— 那会让读者以为公司只值那么多。

门槛比例由分析师定，不设默认值。**这一项存废由分析师决定**：不设门槛就只报内在价值与目标价，不报买入价。若设门槛：

- 若门槛取 25%，则现价须低于内在价值 × 75% 才进入买入区间
- 等价说法：内在价值相对现价须**严格大于** 33.33%（`0.75 × IV > P` ⟺ `IV / P > 1.3333`）。**恰好等于 33.33% 时安全边际为零**，不算达标 —— 写门槛时把这点说清，别写成「≥」

## 七、分歧诊断（替代原来的「强制中性」）

主估值与两个对照的偏离可能差得很远。**先诊断，不强行调和，也不因为方向不同就直接投降。**

### 诊断顺序

1. **口径是否一致** —— 归属口径、预测年度、利润口径、资本结构假设
2. **假设是否可比** —— 增长率、利润率、折现率是不是同一套逻辑
3. **哪个假设在驱动差异** —— 逐个换掉再算，看差异缩小到哪一步
4. **是否有数据缺口** —— 缺的那块是不是恰好决定了差异方向

### 出口

- **诊断得清** → 结论以**主估值**为准，写明两个对照各为什么偏离，以及偏离是否反而支持主估值（例如可比倍数被低利润同业抬高，那主估值的偏低反而更可信）
- **诊断不清** → 评级落 **HOLD**，并在同一页显式写明：**「因主估值与对照方法的分歧未能解释，本次评级不构成方向性判断。」** 同时列出还需要补什么证据

**校赛抬头必须填 BUY / HOLD / SELL 三档之一**，所以这里的出口只有 HOLD 一种，不用「暂不形成评级」这类自造档位 —— 但 HOLD 后面必须跟上那句披露，不能只写个 HOLD 就算完。

### 三条禁止

- **不把分歧当成可靠性概率** —— 原来那套「方法一致性百分比」已经取消。一致性高不高不是概率，**关键证据够不够硬、敏感性测没测全**才是
- **不强行调和** —— 折中成一个谁都不支持的数，比如实报分歧更糟
- **不悄悄丢掉最悲观的那一路** —— 丢掉它，结论必然偏乐观

## 九、交棒

分两次交接，中间隔着人在回路第 2 个节点：

**第一次（证据 + 候选假设，尚无正式估值数字）** 汇报：口径核验三项的结论、数据门槛检查结果（哪几路可执行、FCFE 能不能做、哪几路降级）、统一模型骨架搭好没有、合成数据自测通过没有、假设表里有几项 `[估算]`、识别出几条定性风险。然后停下等确认 —— **这一棒不产出任何作为结论的估值数字**。

**第二次（正式计算完成后）** 汇报：评级、主估值区间、12 个月目标价、另两路的偏离与解释、分歧是否已解释、**假设版本与模型结果版本是否一致、独立复算有没有对上、门禁检查过没过**、有几项降级或无法执行，并说明文件落在哪。

然后停下等**分析逻辑审查（第 3 个节点）** —— 逐年预测的因果链是否成立、可比集合选得对不对、结论有没有过度外推。

**不越过节点自动往下走。**

## 必须遵守的规则

1. **不编数**。假设没依据就标 `[估算]`，列进假设表等确认。**数据不足以估值时就说不足**，不拿估算值凑一个确定结论。
2. **只在 `analysis/valuation.md` 写入**，不碰 `raw_data/` 和 `output/`；模型程序与数据落在 `model/`、`tools/model/`，不往 `raw_data/` 写。
3. **FCFE 是硬性要求，不许省**。校赛明文规定估值必须包含 FCFE 模型。数据不够就写明卡在哪、怎么降级，但不能跳过这一路不写。
4. **不做加权合成**。三路各有角色，不合成一个加权点值，也不用「方法一致性」「信号强度」这类百分比当可靠性指标；**不设默认情景概率，也不设默认安全边际折价**。
5. **现金流与折现率匹配**。FCFF 配 WACC、FCFE 配 Ke；WACC 的 D 是**有息债务市值**，不是净债务。
6. **逐年预测，不套固定增长率**。收入按销量 × ASP 或分业务线驱动；备货的释放与减值两个分支都要建。
7. **口径先核再算**。基准日股数、模型归属口径、净借款取数路径 —— 三项没核完不开始算。
8. **禁止跨倍数比较**。EV/EBITDA 与 P/E 不能直接比数值大小。
9. **三个价格分开写**。基准日内在价值、12 个月目标价、买入门槛价各是什么就说是什么，**不得把打折后的价格叫内在价值**。
10. **分歧先诊断，诊断不清就 HOLD + 披露**。不强行调和，不悄悄丢掉最悲观的一路。
11. **先列假设，确认后再算**。审批前可以做历史计算、口径核验、模型搭建、合成数据测试；**但未经确认的预测假设不得用于输出正式估值、评级、目标价**。
12. **确认记录不得预填**。`approved.yaml` 必须含真实确认人、确认日期、假设版本；空模板就是空模板，**AI 不替分析师签名**。
13. **单一数字源，且由程序生成**。所有对外数字只从 `model/results/` 出，报告里的表整段贴生成结果，人不手改；假设一改就重跑，版本号递增，全文引用逐处核对。
14. **缺失数据不得默认为零**。程序遇到必需输入缺失要报错，不静默按 0 算；确实要按某个值处理，写进假设表并标注依据。
15. **输出前独立复算 + 门禁检查**。换一条路径重算 FCFE / Ke / 终值 / 三情景，对不上就先查错；再跑门禁，拦下 `deprecated` / `candidate` 数字与版本不一致的结果。**来源是 A 级不代替这两步。**
