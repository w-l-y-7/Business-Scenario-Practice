# news-monitor：新闻舆情采集

搜一家上市公司近期（默认 30 天）的新闻，按类别归拢、按情绪标注，落成 `raw_data/news/` 下的一个文件。

**产出是原材料 + 一层表面的归类，不是对公司的判断。** 下游 company-analyst 和 report-writer 建在这份文件上。你的活儿是把报道记准、记全、把情绪标注的依据留痕 —— 至于这家公司值不值得投，不在这一棒。

## 速查表

| 场景 | 怎么处理 |
| --- | --- |
| 同一条新闻多处转载 | 只留**首发或最权威**的那家，不重复建档 |
| 自媒体、论坛帖、微信群截图 | **D 级，默认不收** |
| 公司官网新闻稿、业绩说明会 | C 级，收，但标「公司自述」 |
| 只拿到标题、拿不到正文 | 情绪标「（标题级）」，并在采集说明里声明 |
| 情绪标注 | **必须附判断依据**，引标题或正文里的关键词 |
| 出现监管立案、诉讼、业绩变脸等 | 进「重大事件」节，**单条即可把整体评级下调一档** |

## 一、动手前先定三件事

1. **标的** —— 公司名称 + 证券代码
2. **时间窗口** —— 默认近 30 天；用户说了别的就按用户的
3. **输入形态** —— 有没有新闻正文

时间窗口按**发布日期**算，不按转载日期。

## 二、搜索与过滤

1. 搜目标公司名称 + 股票代码的近期新闻
2. **同一条新闻多个转载 → 只留首发或最权威的那家**。同一事件不同媒体的解读文章算**不同条目**，但要在备注里点明它们说的是同一件事，别让下游以为是两个独立事件。
3. **按来源等级过滤**（照 `data-standard.md` §四）：

| 等级 | 是什么 | 收不收 |
| --- | --- | --- |
| A | 交易所公告、公司公告原文 | 直接收 |
| B | 券商研报、Wind / 同花顺 / 东方财富 Choice 等数据终端 | 直接收 |
| C | 财经媒体报道、公司官网新闻稿、业绩说明会问答 | 收，标「据媒体报道」或「公司自述」 |
| D | 自媒体、论坛帖、微信群截图、未具名「据知情人士」 | **默认不收** |

「营销软文」不单独判断 —— 判断标准不客观，每个人看都不一样。改由来源等级兜住：无署名的自媒体内容本来就是 D 级，进不来；有媒体署名但内容偏推销的，按 C 级收进并标注，由下游权衡。**有客观依据的过滤，比凭感觉拦稿可靠。**

## 三、逐条标注

每条新闻记六项，另加一项「依据」：

| 字段 | 说明 |
| --- | --- |
| 标题 | 新闻标题原文，不改写 |
| 来源 | 媒体名称（+ 可信度等级） |
| 日期 | **发布日期**（不是转载日）；推断的标「（推断）」 |
| 类别 | 业务 / 政策 / 市场 / 管理层 / 其他 |
| 情绪 | 正面 / 中性 / 负面 |
| 摘要 | 一句话概括，**不超过 30 字** |
| 依据 | **为什么标这个情绪** —— 引标题或正文里的关键词 |

### 3.1 情绪必须有依据

情绪是**你对报道措辞的归类**，不是事实。没有依据的情绪标记等于编数，只不过编的是判断而不是数字。

标了「正面」就要能指回一个词：

```
情绪：正面 ｜ 依据：标题含「净利润翻倍」「创新高」
情绪：负面 ｜ 依据：正文含「收到深交所问询函」
```

指不回去的，就把情绪改成「中性」并说明「措辞无明显倾向」。

### 3.2 只拿到标题时

这个环境下检索工具常常只返回标题和链接，不返回正文。这种情况：

- 照常标情绪，但后面加**「（标题级）」**
- 在「采集说明」里声明：

> 检索工具只返回标题与链接，**未返回正文**。本文件全部为标题级信息，情绪标注基于**标题措辞**，未经正文核对。

不写这句，下游会以为你读过正文 —— 而标题党、反讽、中性标题掩盖负面内容是常态。

### 3.3 类别

默认五类：业务 / 政策 / 市场 / 管理层 / 其他。条目多时可在类别下再分子类（业绩、资本运作、合作与技术、资金面等），但**大类不要改名**，方便跨公司比较。

**注意主体**：集团层面、子公司层面、关联方的事，标题里常常写成公司名。凡是非上市公司本体的事项，必须在备注里点明（如「涉及新紫光集团，非上市公司 000938 本体事项」）。

## 四、整体情绪评级

### 4.1 先给分布（这是事实）

| 情绪 | 条数 | 占比 |
| --- | --- | --- |
| 正面 | | |
| 中性 | | |
| 负面 | | |
| 合计 | N | 100% |

### 4.2 再给标签（这是判断）

阈值按**互斥顺序**判定，先看负面：

- 负面占比 ≥ 40% → **整体负面**
- 否则正面占比 ≥ 60% → **整体正面**
- 其余 → **中性**

先说清楚这条规则的两个局限，别让下游高估它：

1. **按条数算，不看轻重**。10 条正面软文配 1 条监管立案，纯按条数也会判成正面 —— 所以才有下一节的「重大事件」覆盖机制。
2. **负面新闻是最容易漏检的**。检索工具对负面消息（尤其是未被大范围转载的监管、诉讼类）命中率明显更低。

所以整体标签后面**必须**跟这句声明，一个字不改：

> 本评级按已检到的 N 条报道计算，未加权；**未检到负面不等于负面不存在**。这是报道口径的情绪分布，不是对基本面的判断。

### 4.3 重大事件单列

以下事件**单条即可把整体评级下调一档**（正面 → 中性，中性 → 负面，负面保持）：

| 事件类型 | 例子 |
| --- | --- |
| 监管 | 立案调查、问询函、处罚决定、警示函 |
| 诉讼 | 重大诉讼、仲裁、被强制执行 |
| 业绩 | 由盈转亏、业绩大幅下修、审计意见非标 |
| 治理 | 实控人/高管被查、大额减持、控制权变更 |
| 财务 | 债务违约、评级下调、商誉大额减值 |

单列一节记录：**事件、类别、日期、来源、等级、对整体评级的影响**。没有就写「本节无内容」—— 但要记住，这一节空着**不代表没有这类事件**，只代表这轮没检到。

## 五、来源与数字格式

- 正文里的每个数字按 `data-standard.md` §1.1 标来源，格式照抄：
  `归母净利润 21.67 亿元（来源：上海证券报，2026-08-28，C 级）`
- 数字格式照 §三：金额亿元 2 位小数、百分数 2 位小数、日期 YYYY-MM-DD。
- **行情数据**（融资融券、主力资金、股价）来源标成「行情数据（来源：XX，日期）」，**不要标成新闻** —— 新闻只是转述了行情数据，真正的来源是行情源。

## 六、提不到的数怎么标

| 情况 | 怎么写 |
| --- | --- |
| 日期是推断的 | `2026-08-28（推断）` 或 `[待核实]` |
| 来源说不清是谁发的、什么时候发的 | `[待核实]` + 说明卡在哪 |
| 来源里确实没有这项 | 「未披露」 |
| 该对比不适用 | 「—」 |

**四条禁止**：不编数、不用记忆里的数、不编链接、不因为「这里应该有个数」就补一个。

## 八、交棒

写完汇报四件事：**时间窗口、共几条、情绪分布和整体标签、缺什么**，并特别说明「负面类新闻本轮检到几条 —— 没检到不等于没有」。

然后**停下**。数据源确认是项目 `CLAUDE.md` 第五节的第 1 个「人在回路」节点，必须等分析师确认数据是否齐全、是否可靠，才轮到下游接棒。

## 必须遵守的规则

1. **不编数、不编链接、不编日期、不编事件**。说不清的一律标 `[待核实]`。
2. **只在 `raw_data/news/` 下写入**，不碰 `analysis/`、`output/` 和 `raw_data/` 的其他子目录。
3. **情绪必须附依据**。没有依据的情绪标记等于编数，只不过编的是判断。
4. **D 级来源不收**。有客观依据的过滤，比凭感觉拦稿可靠。
5. **整体评级必须带那句声明**。「未检到负面不等于负面不存在」是本技能最容易被忽略、后果最重的一条 —— 漏掉它，下游会拿一个系统性偏乐观的结论去做风险分析。
6. **不越人在回路节点**。采集完即停，等第 1 个节点确认。
