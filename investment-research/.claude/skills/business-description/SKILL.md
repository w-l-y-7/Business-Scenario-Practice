# business-description：公司业务描述

读 `raw_data/earnings/`（财报）和 `raw_data/reports/`（券商研报的公司概况部分），产出 `analysis/business.md`，对应 CFA 研报第 ① 节 Business Description。

**这一节是整份研报的门面。** 评委读完 Business Description 就该知道这家公司靠什么赚钱、钱从哪来、谁在管。写成「公司成立于 X 年，是一家领先的 XX 企业」这种官网简介腔，等于白给。

## 速查表

| 项 | 要什么 | 数据来源 |
| --- | --- | --- |
| 公司概况与沿革 | 成立时间、上市时间与板块、注册地、主营业务一句话定义、重大沿革（并购、重组、转型） | `raw_data/earnings/`、公司公告 |
| 产品与服务 | 主要产品线、各自用途、技术代际或规格档次 | `raw_data/earnings/`、`raw_data/reports/` |
| 收入构成 | **分部收入占比 + 地区收入占比**，近三期趋势 | 财报「分部报告」附注 |
| 客户与供应商集中度 | 前五大客户收入占比、前五大供应商采购占比 | 财报附注 |
| 管理层与股权结构 | 董事长 / 总经理背景、核心技术人员、前十大股东、实际控制人、股权集中度 | 财报「公司治理」章节、公告 |
| 发展战略 | 公司自述的战略方向、在建项目、募投项目进展 | 财报「管理层讨论与分析」 |

**六项缺哪项就标哪项**，不要用「公司治理结构完善」这类话把空缺糊过去。

## 一、动手前先定三件事

1. **标的与报告期** —— 读哪份财报文件
2. **行业** —— 决定用哪套产品分类口径
3. **数据可得性** —— 先通读 `raw_data/earnings/`，逐项核对六项各拿得到多少

**先数一下六项里有几项是「有据」的。** 六项全缺时，这份报告的主要结论应该是「公开材料不足以描述这家公司」，而不是硬凑一篇简介。

## 二、六项怎么写

### 2.1 公司概况与沿革

- 主营业务用**一句话**说清，且要具体到「卖什么给谁」，不写「专注于 XX 领域」
- 沿革只写**改变公司业务结构的事件**（并购、剥离、主业转型），不写「成立 XX 周年」这类流水账
- 上市信息写清板块（主板 / 创业板 / 科创板）和上市时间

### 2.2 产品与服务

- 按产品线分列，每条写清**用途 + 技术档次 + 在公司收入中的位置**
- 有技术代际的公司（如光模块的 400G / 800G / 1.6T）要**标明代际和各自占比**
- 不写「产品性能优异」「技术领先」这类无出处的形容词

### 2.3 收入构成（这一项最容易被漏）

**分部收入占比和地区收入占比都要，且要近三期。** 只写「主营业务收入 X 亿元」没有任何信息量 —— 评委要看的是**收入结构在往哪变**。

| 维度 | 当期 | 上期 | 上上期 | 趋势 |
| --- | --- | --- | --- | --- |
| 分部 A 占比 | | | | |
| 分部 B 占比 | | | | |
| 境内收入占比 | | | | |
| 境外收入占比 | | | | |

数据来自财报**分部报告附注**。拿不到就标 `[待核实]` 并说明找过哪些来源 —— 分部数据缺失会直接影响行业分析和风险分析，要在缺口节里点明。

### 2.4 客户与供应商集中度

- 前五大客户收入占比、前五大供应商采购占比，**逐期列出并标趋势**
- 集中度上升要说清是**主动选择**（绑定大客户）还是**被动依赖**
- 这条直接喂给 `industry` 技能的「客户议价能力」一力，两边数字必须一致

### 2.5 管理层与股权结构

- 董事长 / 总经理 / 核心技术人员的**从业背景**，不写「经验丰富」
- 前十大股东及持股比例、实际控制人、**股权集中度**（第一大股东占比）
- 有股权激励、员工持股计划的要写出**行权条件**（这是治理分析的关键输入，见 `esg` 技能 §3.4）

### 2.6 发展战略

- 写公司**自己披露的**战略方向和在建 / 募投项目进展
- 标明这是**公司自述**（C 级），不是独立判断 —— 判断归 `industry` 和 `valuation`
- 不把公司的战略口号当成既成事实

## 三、联网补数据（走 data-collector，不自己落盘）

公司官网、交易所公告这类公开信息可以联网补，**但不由本技能直接写入 `raw_data/`** —— 那是 `data-collector` 的地盘（照 `CLAUDE.md` 第一节的「禁止跨目录写入」）。

流程：

1. 本技能识别出缺哪几项（如分部收入、股权结构）
2. 请求 `data-collector` 采集对应材料，按 `data-standard.md` §1.2 补来源块后落盘
3. `data-collector` 交回后，本技能再读 `raw_data/` 写报告

**联网拿到的信息同样要标来源和可信度等级**。公司官网新闻稿是 C 级，交易所公告是 A 级 —— 官网自述不能当作独立事实。

## 五、交棒

写完汇报：**六项里有几项有据、缺的是哪几项、有没有走 data-collector 补数、什么数据缺口**，并说明文件落在哪。

然后**停下**，等「人在回路」第 3 个节点（**分析逻辑审查**）：收入结构的变化有没有被过度解读、新业务的表述有没有超出公司披露范围。

**不越过节点自动往下走。**

## 必须遵守的规则

1. **不编数，也不编业务描述**。「行业领先」「技术先进」这类无出处的话一律不写 —— 业务描述比财务数字更容易混进想当然的表述。
2. **只在 `analysis/business.md` 写入**，不碰 `raw_data/`（要补数走 `data-collector`）和 `output/`。
3. **公司自述与独立判断分开**。战略、愿景、竞争优势这类公司自己说的话，标明是公司表述（C 级），不当成事实。
4. **分部与地区数据缺失要显式标出**。它是下游 `industry` 和 `valuation` 的输入，悄悄略过会让那两节建立在错误假设上。
5. **集中度数据与 `industry` 保持一致**。同一组前五大客户占比，两份报告里不能出现两个数。
6. **不越人在回路节点**。分析逻辑要等确认。
