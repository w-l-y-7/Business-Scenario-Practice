# assumptions/ —— 候选假设与已确认假设

两个文件，一份是**打算这么预测**，一份是**分析师签过字的**：

| 文件 | 状态 | 能干什么 |
| --- | --- | --- |
| `candidate.yaml` | `candidate` | 算历史指标、核口径、搭模型、跑合成数据测试 |
| `approved.yaml` | `approved` | 出正式估值、评级与目标价 |

`approved.yaml` **不由 AI 预先创建**。分析师在「人在回路」第 2 节点确认后，复制 `candidate.yaml`、把 `status` 改成 `approved`、亲手填 `confirmed_by` 与 `confirmed_on`，才出现这份文件。**AI 不代签名、不预填、不把状态预先写成已确认。**

## 状态取值

| 状态 | 成品能不能引用 |
| --- | --- |
| `approved` | 能 —— 且要版本一致 |
| `candidate` | 不能。只能用于测试与讨论 |
| `deprecated` | 不能。旧方法、旧口径 |
| `superseded` | 不能。已被新版本取代，看 `superseded_by` |

## 三行不设默认值

**情景概率、任何形式的估值权重、安全边际折价** —— 没有依据就不预设。预设了等于替分析师做判断。

## 假设被改动怎么办

版本号 +1，重跑模型。**不要把旧数字留在结果文件里冒充新结果** —— 旧结果标 `superseded` 并写明被谁取代。

## 写假设的两个要求

- **「销量 × ASP」比「收入增速」好** —— 「出货量受产能限制只能增 30%」是可验证的判断，「收入增速 35%」不是。两个都给，不要只写一个。
- **每一项都要有依据。** 有来源的标来源，没来源的标 `[估算]` 并说明依据。这张表就是「人在回路」第 2 节点的审查对象。
