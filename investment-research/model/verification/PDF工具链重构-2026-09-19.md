## 撞出来的四个真问题

前三个都是**编译不报错、只有成品悄悄不对**的那一类，靠试排才发现。

### 1. pandoc 静默丢掉围栏 div —— 这是个存在已久的隐性缺陷

`::: {.source} ... :::` 在 LaTeX 输出里**只剩内容、外壳没了**。用最小样例确认：

```
::: {.source}
来源内容
:::
```
`pandoc -t latex` 输出 → `来源内容`，wrapper 消失。

**后果**：`header.tex` 里的 `source` 与 `placeholder` 环境**从建起来那天就没被调用过**。
来源块没按 8–9 pt 排、占位块没按「一眼可辨」排，而编译一声不吭。
旧版试排之所以「四项全过」，是因为检查只看文字在不在 —— **文字确实在，样式没生效**。

**修法**：新增 `divs-to-latex.lua`，把 `cover` / `backcover` / `source` / `placeholder`
四类 div 转成同名 LaTeX 环境，并递归处理嵌套（封面里放占位块是常见写法，
而 pandoc 的过滤器一旦返回替换值就不再进入内部，不自己往下走会漏掉嵌套的）。

### 2. pandoc 默认模板不加载 `graphicx`

不补这一行，文稿里的 `![](figures/x.png)` **根本编译不过**。
即本轮不加图片目录，这个坑也还在，只是没人踩到。

### 3. `build.ps1` 必须带 UTF-8 BOM

PowerShell 5.1 读 `.ps1` 时没有 BOM 就按系统 ANSI 码页解码。脚本里全是中文，
丢了 BOM 直接语法错误：`Unexpected token '鐢熸垚鎴愬姛锛?'`。
本轮写文件时确实丢过一次，已补回并写进 `tools/pdf/README.md`。

### 4. 封面必须是文档的第一个元素

`cover` 环境靠 `\clearpage` 起新页。若封面之前还有内容，那段内容会被单独推成一页
**并且带着页码**，`\thispagestyle{empty}` 则落到封面那一页 —— 表现为「封面没页码、
前一页有页码」，页码整体错位一格。试排稿首版就是这个结构，实测暴露。
已在 `tools/pdf/README.md` 写明封面要放最前。
