# verification/ —— 核验记录

模型算得出来，不等于算得对。这个目录存的是**「我核过了」的证据**，不是结论本身。

一任务一文件，文件名体现核了什么，如 `口径核验-2026-09-18.md`、`风险进模型核查-2026-09-18.md`。

## 必核的几项

| 核验项 | 谁做 | 核什么 |
| --- | --- | --- |
| **口径核验** | `financial-analyst` | 基准日股数与最近报告期末的差异、利润与现金流归属口径、净借款取数路径 |
| **报表勾稽** | `financial-analyst` | 净利润 → 经营现金流 → 自由现金流的桥对不对得上 |
| **债务现金桥** | `financial-analyst` | EV → 股权价值的桥里，债务与现金取数对不对 |
| **风险进模型核查** | `risk-analyst` | 定性清单上每条高影响风险，有没有对应的模型假设与情景 |
| **独立复算** | 分析师 | 手工复算关键几步，与程序结果对得上 |

## 记录怎么写

每条核验写清四件事：**核的是什么、用什么方法核、结果对不对、不对的话卡在哪**。核不过的**不写「已修正」了事**，写真话 —— 退回哪一环、等谁补。

**「已配置」「已测试」「已跑通」要分开说。** 配置了不等于测过，测过不等于跑通。含混其词一旦被追问，比如实说「还没跑」难看得多。
