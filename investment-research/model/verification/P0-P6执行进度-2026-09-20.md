### 已实测通过的行为

- 输入校验：单位 / 币种 / 四个日期 / 来源引用完整性
- 目标日 = 估值基准日 + 12 个月（不等直接报错）
- 财年历**从历史报告期推导**（只认 12 个月完整期，半年报期末不算财年末）
- 目标日与预测期第一年年度末**不对齐时如实报出**，并标「需团队确认」
- 基期年化：半年报流量项 ×(12/月数)，存量项不年化
- FCFE 两条路 + 差额桥（差额 = 非现金项 − 三类之外的 ΔNWC）
- FCFF 两条路 + 同一差额桥（盈利年份下代数恒等）
- 股本桥、限制性股票**两个**勾稽、H 股募集资金现金桥（净额缺失时**不给 pro forma 数**）
- 固定资产滚动：上年末 + 资本开支 − 折旧摊销 = 本年末
- 目标价重估勾稽：显式重估 = V₀×(1+Ke) − FCFE₁，实测差 0.0
- 朴素写法与显式重估的差 = 第一年每股分红
- 情景排序 Bear ≤ Base ≤ Bull；**不预设概率、不给加权期望值**
- 敏感性方向：Ke↑ 价值↓、DIO↑ 价值↓、毛利率↑ 价值↑
- 假设登记：覆盖面检查 + **登记取值与文件取值一致性检查**
- 门禁五项（状态 / 版本 / 废弃 / 日期 / 来源）
- 渲染片段自带版本与状态标记，且**不会顶替报告的版本块**

## 本轮测试暴露并修掉的缺陷（都是真问题，不是测试写错）

1. **反向估值把有解说成无解。** 隐含收入增速的目标函数**非单调**：增速越高，
   营运资本占用涨得越快，自由现金流反而塌下去，每股价值先升后降。区间两端同号时
   原来的代码直接报「无解」，而中间其实有两个解。改成先在区间里扫符号变化，
   找到那一小段再收敛；多个解时取**离基准最近**的那个并在结果里写明还有别的解。
2. **行情块从来没人校验。** `meta.market_quote` 一直躺在输入文件里没有任何检查 ——
   前复权价、请求日与实际交易日不符、失败状态却带正数价，这些 `MarketQuote` 里
   写好的规则全都没生效。现在 `load_inputs` 会校验它，并核对它与 `latest_price`
   说的是同一个价（不一致说明其中一个没跟着改，报告里会出现两个市价）。
3. **固定资金滚动检查根本不存在。** `ppe_net` 被登记为勾稽字段、`errors.py` 也把
   固定资产滚动列为应有的桥，但没有任何代码用它。已补上。
4. **两个勾稽字段没登记，缺了会悄悄跳过检查。** `articulation()` 读 `ebit` 与
   `net_income`，但两者都不在 `ARTICULATION_PERIOD_FIELDS` 里 —— 缺了不报缺口，
   检查静默降级成「未检索」。已补进字段清单。
5. **日期格式写错报的是「缺失输入」。** `_norm_date` 对格式错误的日期抛
   `MissingInputError`，会把人引去补一个已经填过的字段。改成 `SchemaError`。
6. **渲染片段没有版本标记。** 表格粘进报告后，与模型对不对得上没人看得见。已加顶部标记，
   并**刻意避开 `**假设版本**：` 这种粗体写法** —— 门禁按那个格式比对版本，片段若写成一样
   会抢先匹配，把后面写错的版本盖住。
7. **README 说门禁会在三口径分歧超阈值时阻塞输出 —— 没有这回事。** 阈值是团队要定的数，
   AI 不能预设。已在 README 里写明这条未实现，并补出门禁实际检查的五项。

## 从年报缺口回填里得到的两条口径结论（重要，别丢）

1. **研发费用是利润表独立一行，不得并进管理费用。** 这正是 `operating_expenses`
   口径最容易出错的地方。
2. **税金及附加在营业总成本内、营业成本外。** 已用恒等式验证：
   `营业成本 + 税金及附加 + 销售 + 管理 + 研发 + 财务 = 营业总成本`。

另外记一条待核对的差异：`historical.yaml` 把 2024A `total_assets` 的页码标成 p.96，
实际出现在 p.93/p.94。两份文件的页码来源不一致，合并时一并订正。
