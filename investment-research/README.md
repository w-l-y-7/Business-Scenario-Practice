# investment-research

上市公司深度研究项目 —— 目标是一份符合 **2026 年 CFA 投资分析比赛校赛**要求的英文投资研报。

**比赛硬性要求**：正文全英文、PDF 提交、A4、正文 ≤ 10 页、附录 ≤ 10 页、每页标页码、封面封底用 CFA 规定模板且不计入正文、使用 AI 必须注明、引用须标来源、计算底稿须保留。完整规则见 [.claude/rules/output-format.md](.claude/rules/output-format.md) 第一节。

```
---
免责声明：本报告由 AI 辅助生成，仅供研究参考，不构成投资建议。
所有数据和分析结论需经专业人士独立核验后方可用于投资决策。
数据截至 [日期]，不保证信息的完整性和时效性。
---
```

## 它怎么工作

五个阶段，原料从左边进，成品从右边出：

| 阶段       | 核心任务                                                | 负责 agent                                 | 调用 Skill                                                                           | AI 自主度 |
| ---------- | ------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------ | --------- |
| 信息采集   | 财报 / 研报 / 新闻 / 公告四路并行抓取；行情数据另行采集 | `data-collector`                         | `earnings-extract`、`report-digest`、`news-monitor`                            | 高        |
| 多维分析   | 公司 / 财务两组独立评估，产出五份中间报告               | `company-analyst`、`financial-analyst` | `business-description`、`industry`、`esg`、`financial`、`valuation` | 中        |
| 风险分析   | 提炼风险清单（第六份），并建量化风险情景                | `risk-analyst`                           | `risks`                                                                            | 中        |
| 报告生成   | 组装成品英文研报（**只呈现，不建内容**）          | `report-writer`                          | —                                                                                   | 中        |
| 审阅与迭代 | 人在回路节点逐项检查，按审阅意见修正                    | 分析师 +`report-writer`                  | —                                                                                   | 低        |

**AI 自主度**指这一阶段 AI 能自己推进到什么程度：高 = 按既定规则跑完；中 = 关键节点停下等确认；低 = 分析师主导，AI 只做执行。

```
① 采集            ② 分析                 ③ 风险            ④ 撰写            ⑤ 审阅
data-collector →  company-analyst   →  risk-analyst  →  report-writer →  分析师主导
                  financial-analyst                                    ↺ 回 ④ 修正

raw_data/          analysis/            analysis/risk     output/
```

**风险内容在分析阶段建立（③），不在撰写阶段补。** 撰写方拿到的是已经定稿的风险清单和情景，只负责译成英文、按章节呈现 —— 它不决定有哪些风险、影响多大。

**数据单向流动，且禁止跨目录写入**：`raw_data/` 由 data-collector 独占写入，`analysis/` 由两位分析师写入，`output/` 由 report-writer 写入。上游可以只读，下游不许回头改上游。

## 成品结构

```
【封面】CFA 协会规定模板 —— 不计入正文

【正文第 1 页开头 —— 七项必填】
Company / Exchange / Ticker / Industry / Recommendation / Current Price (as of 日期) / Target Price (±%)

① Business Description
② Industry Overview and Competitive Positioning
③ Investment Summary
④ Valuation（FCFE 逐年预测为主估值，校赛必含）
⑤ Financial Analysis
⑥ Investment Risks
⑦ Environmental, Social, and Governance（E、S、G 三块都要写；治理是 G 的核心块）

References
AI Usage Disclosure
Appendices（数据来源清单 + 计算底稿）

【封底】CFA 协会规定模板 —— 不计入正文
```

页数配比（正文 10 页封顶）：抬头 + Investment Summary 1.00 / Business Description 0.75 / Industry & Positioning 1.25 / Valuation 2.25 / Financial Analysis 1.25 / Investment Risks 1.25 / ESG 1.25 / References 0.50 / Data / AI disclosure 0.50 = 10.00。

**固定标题是项目自我约束，不是赛事原文的规定。** 校赛规定的是必含哪几节，没找到「标题一个字不许改」的明文；沿用固定标题图的是跨版本可比，方向对，但别当成不能问的硬规定。

**四个日期是四件事**：信息截止时间 / 行情日期 / 估值基准日 / 目标日期，目标期限 12 个月。行情日期 ≠ 估值基准日；遇休市取前一个交易日并写出实际交易日。见 `.claude/rules/data-standard.md` §2.3。

## 怎么用

### 跑一轮完整研究

1. 先在 `CLAUDE.md` 的「项目信息」里填上研究对象（公司名称 + 代码）
2. `data-collector` 采集材料 → 进 `raw_data/`
3. ← **人在回路 ①：确认数据是否齐全、是否可靠**
4. `financial-analyst` **先只做口径核验、数据门槛检查与候选假设表，不填任何估值数字**
5. `company-analyst` 出业务描述 + 行业 + ESG（E / S / G 三块）→ 进 `analysis/`
6. ← **人在回路 ②：审查核心假设**（逐年预测假设、终值假设、可比集合、阈值调整）
7. 假设确认后，`financial-analyst` **才正式计算**：逐年预测 → 情景与终值 → 可比与 FCFF 两路对照 → 三个价格 → 独立复算 → 补全 `analysis/valuation.md`
8. `risk-analyst` 提炼风险清单 + 建风险情景 → `analysis/risks.md`
9. ← **人在回路 ③：审查分析逻辑**（因果链、情景传导、有没有过度外推）
10. `report-writer` **先出样张试排 2~3 页**（表格 / 来源括注 / 页码 / 图片 / 附录五项目视通过），再写满全文并组装 → `output/investment-report.md`
11. ← **人在回路 ④⑤⑥：审查结论措辞、免责声明合规、AI 披露合规**
12. 按审阅意见修正 → 回到第 10 步
13. 导出 PDF：套 CFA 封面封底、排页码、核对正文 ≤ 10 页 / 附录 ≤ 10 页

### 材料从哪来

两条路，可以混用：

| 来源                     | 怎么走                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| **网页抓取**       | `data-collector` 按四类技能检索采集（财报 / 研报 / 新闻 / 公告），逐份写来源块后落盘                                          |
| **分析师直接提供** | 把文件交给`data-collector` 归档 —— `raw_data/` 由它独占写入，手工放进去的文件同样要按 `data-standard.md` §1.2 补来源块 |

**来源块是下游能追溯的前提**，不是可选项。直接给的数据缺来源块，下游就无法标注出处，整份报告的数字链条就断了。

行情数据（股价、市值、可比公司倍数）和公司公告（董事会决议、股权变动、审计机构变更）目前都没有专用技能，两条路都走：`data-collector` 直接采集，或由分析师提供。

**下游可以回头要求补采。** 分析师在分析过程中发现缺口（分部收入明细、股权质押比例等），会列清单交回 `data-collector` 补采 —— 这是正常流程。补采仍要写来源块，且仍然只由 `data-collector` 写 `raw_data/`。

### 只做其中一段

可以单独调某一段，不必每次跑全程。但记住：**`raw_data/` 更新后，下游的 `analysis/` 和 `output/` 就过期了**，要么重跑下游，要么在过期文档开头标明数据时点。

## 三条硬规矩

**一、不编数。** 所有引用的数字必须标注来源，格式见 `CLAUDE.md` 第二节。无法确认来源的标 `[待核实]`，并在审阅阶段提醒分析师。细则见 [.claude/rules/data-standard.md](.claude/rules/data-standard.md)。

**二、不要在人在回路节点上自动往下走。** 六个节点（数据源确认、核心假设审查、分析逻辑审查、结论措辞审查、免责声明合规、AI 披露合规）必须停下来等分析师确认。见 `CLAUDE.md` 第五节。

**三、AI 使用必须如实披露。** 校赛明文要求。本项目整条流水线由 AI 驱动，披露要写清用在哪几环、人工把关在哪，**少报或含糊比多报危险得多**。见 [.claude/rules/output-format.md](.claude/rules/output-format.md) 第五节。

**来源升到 A 级，不等于模型变对了。** A 级只说明「数字是公司自己披露的、能逐页回溯」；口径选错、期间混淆、折现假设拍脑袋，算出来的结论照样错，而且错在模型里，来源等级再高也照不出来。判断结论可不可靠要看另外几样：口径核验做了没有、现金流与折现率配没配对、有没有独立复算、敏感性测没测。**这三样都没做的时候，别把「来源是 A 级」当结论可靠的证据。**
