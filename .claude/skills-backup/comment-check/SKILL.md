# comment-check：检查代码注释质量

## 这个技能做什么

检查 Python 代码的注释，从三个角度发现问题：

1. **注释够不够**：目标比例是「10 行里约 7 行代码、3 行注释」（注释占比 ≥ 30%）
2. **注释和代码匹不匹配**：注释说的是不是代码真的做的事，有没有过时或写错
3. **适不适合小白看**：注释是否解释了「做什么、为什么」，用词是不是大白话

只做检查报告，**不改代码**。

## 检查步骤

### 第一步：确认要检查的文件

先问清楚用户要检查哪个文件（比如「检查一下番茄钟.py 的注释」），拿到具体文件名再动手。**不要**默认扫整个项目——全项目检查又慢又费 token（花费大），用户明确要查哪个就只查哪个。

### 第二步：跑统计脚本拿客观数据

用技能自带的统计脚本，**指定要检查的文件**：

```powershell
python .claude/skills/comment-check/scripts/comment_ratio.py <文件路径>
```

- 查一个文件就给一个路径
- 想一次查多个就空格隔开，比如 `python comment_ratio.py a.py b.py`
- 脚本会输出每个文件：总行数、代码行、注释行、文档行、注释占比、达标情况

### 第三步：读代码核对

拿到脚本统计后，**再读一遍被测代码**，重点查：

- **每个函数/类有没有说明**？文档字符串（docstring）或上方的注释
- **关键逻辑有没有解释**？复杂的 if、循环、算法、数字（魔法数字）要说明「为什么这么做」
- **注释和代码对得上吗**？有没有注释写的是旧逻辑、或者张冠李戴
- **是不是大白话**？有没有「定义变量 x」这种废话注释、术语堆砌、或者只有英文没解释
- **空文件**（脚本显示总行数 0）不用报告成缺注释，标一句「空文件」即可

### 第四步：对话里输出报告

按文件逐个报告，固定格式：

```
## 注释检查报告

### 文件：xxx.py
- 注释占比：xx%（目标 30%）→ 达标 / 欠注释 / 严重缺注释
- 函数/类的注释情况：哪些有说明、哪些没有（点名）
- 注释与代码匹配：良好 / 有 x 处对不上（举例：哪一行注释写了什么、实际代码是什么）
- 小白视角：合格 / 有问题（举例：哪句注释没解释原因、哪个术语没说明）

### 汇总
本次检查 X 个文件：几个达标、几个欠注释、几个严重缺注释
```

报告要求：

- **比例用脚本的客观数据**，不要自己估
- 匹配度和小白视角靠读代码判断，**每个问题都要举具体例子**（哪一行、注释写了什么、哪里不对）
- **不堆术语**，结论让不懂编程的人也能看懂
- 达标的好文件也要表扬一句，比如「main.py 每个函数都有说明」
