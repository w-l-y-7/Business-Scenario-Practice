# unit-test：给代码写单元测试并出报告

## 这个技能做什么

1. 分析指定的 Python 代码，找出值得测试的逻辑函数
2. 用 **unittest**（Python 自带测试框架，无需安装）写测试文件
3. 执行测试
4. 在对话里输出清晰的测试报告（不生成文件）

## 安全红线（最重要，任何时候都别违反）

被测程序可能带着**真实数据**（比如记账 app 有 `records.db`）。测试如果直接写进真实数据库，会毁掉用户的数据。

- 测试前必须先隔离数据：把被测模块的数据库路径变量改成临时路径。
  例：`import main` 之后执行 `main.DB_PATH = <tempfile 生成的临时路径>`。
- 测试结束后删除临时文件。
- 动手前先读被测程序的数据层代码，搞清楚数据库路径是怎么定义的，再决定怎么隔离。看不懂就不动手。

## 工作步骤

### 第一步：分析代码

读目标 .py 文件，把值得测的函数列出来：

- **优先测纯逻辑函数**：输入→输出可以预期，比如计算、汇总、统计、查询、增删改
- **不测 GUI 类**：界面相关代码（Tkinter 的 App 类）一般跳过，只测背后的逻辑函数

### 第二步：写测试

- 用 unittest 框架，测试文件命名 `test_<被测文件名>.py`
- 放在**与被测文件同一个目录**（这样 import 才不会报错）
- 每个函数至少覆盖三类情况：
  - 正常输入 → 期望输出
  - 边界情况（0、空、负数、空列表）
  - 异常情况（非法参数怎么处理）
- 如果被测代码用到数据库：在 `setUp` 里建临时库并建表，在 `tearDown` 里清掉，保证每个测试独立干净

### 第三步：执行测试

在**被测文件所在目录**运行：

```powershell
python -m unittest test_<被测文件名> -v
```

注意：`-v` 会显示每个测试的具体结果，报告更详细。

### 第四步：在对话里输出报告

测试跑完后，按固定格式汇报：

```
## 单元测试报告
被测文件：xxx.py
被测函数：add_record, get_summary, ...（逐个列出）

结果：共 X 个测试，通过 X 个，失败 X 个，报错 X 个

失败/报错详情（每个都讲成人话）：
- 测试名：原因是什么、哪一步出了问题、和期望差在哪

结论：用一句话总结代码质量（稳定 / 有小毛病 / 有明显问题）
```

- 失败 = 测试跑完了但结果不对（逻辑可能有 bug）
- 报错 = 测试根本没跑完（可能代码抛异常）

报告要求：**不用术语堆砌**，把每个失败/报错的原因翻译成大白话，让不懂编程的人也能看懂。
