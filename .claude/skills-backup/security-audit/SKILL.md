# security-audit：检查代码安全隐患

## 这个技能做什么

检查代码里四类安全隐患，只出检查报告，**不改代码**：

1. **敏感信息泄露**：密码、API 密钥、token、私钥等直接写在代码里，或写进会被提交的配置文件
2. **SQL 注入风险**：把用户输入直接拼进 SQL 字符串（f-string、加号拼接、format、%），而不是用 `?` 参数占位符
3. **配置文件明文敏感信息**：配置文件里写明文密钥；`.env` 文件本身要确认已加进 `.gitignore` 且没被提交
4. **其他危险的写法**：`eval`/`exec`、`os.system`、`shell=True`、`pickle` 反序列化、弱哈希（MD5/SHA1）、关掉证书校验（`verify=False`）、`debug=True` 没关、内网 IP 硬编码等

## 检查步骤

### 第一步：确认要检查的文件

先问清楚用户要检查哪个文件或哪个目录（比如「检查一下每日记账App 的安全」）。**不要**默认扫整个项目——全项目扫描又慢又费 token，用户明确要查哪个就只查哪个。

### 第二步：跑扫描脚本拿可疑点

用技能自带的扫描脚本，**指定要检查的文件/目录**：

```powershell
python .claude/skills/security-audit/scripts/security_scan.py <文件或目录>
```

- 查单个文件就给文件路径；想一次查多个就空格隔开
- 给目录会递归找里面的代码/配置文件（自动跳过 `.git`、`.claude`、`venv` 等目录）
- 脚本输出每个可疑点：`[高危]/[中危]/[提示]` + 行号 + 原因
- 脚本只给「怀疑清单」，不等于实锤，下一步必须核对

### 第三步：读代码核对（关键，别跳过）

对脚本标出来的每个点，**打开原文件逐条核对**：

- **高危是不是真的**？比如脚本看到 `password` 变量名就报，可能它只是普通表单字段名，不是真密钥——点名确认
- **SQL 那条**：看是不是真的把用户输入拼进了 SQL。用了 `?` 占位符传参的是**安全的**，别误报；f-string/加号拼接里带着变量才是真问题
- **eval/exec 那条**：看入参是不是来自用户输入。写死的常量字符串执行问题不大
- **配置文件**：`.env` 里有密钥是正常做法，重点查两件事——有没有加进 `.gitignore`、有没有已经被提交进 git（用 `git ls-files` 查，或翻 git 记录）
- 顺手看看有没有脚本没覆盖、但你一眼觉得不对的地方

### 第四步：对话里输出报告

按文件逐个报告，固定格式：

```
## 安全审计报告

### 文件：xxx.py
- 高危问题：x 处（每个：第几行、问题是什么、为什么危险、怎么改）
- 中危问题：x 处（同上）
- 提示：x 处
- 做得对的地方：比如用了 ? 参数占位符的 SQL、密钥放进了环境变量

### 汇总
本次检查 X 个文件：高危 X 处、中危 X 处、提示 X 处
最该先修的是：……
```

报告要求：

- 高危/中危**逐个点名**：第几行、代码写了什么、危险在哪、小白也能听懂的改法
- **误报要说明**：脚本标了但读下来没问题的地方，直说「这条是误报，因为……」
- 结论说人话，比如「目前没发现会被黑的洞」或「这个密码写死在代码里要赶紧改」
