# 政策简报生成（迭代精修循环）

把政策/研究材料压缩成一篇结构固定、质量可校验的政策简报。核心是**闭环**：不是一次写成，而是「生成初稿 → 检查脚本挑毛病 → 修到它闭嘴 → 再逐条溯源核对事实」最多 3 轮。每轮都基于同一份草稿原地修改、重跑脚本，不要另起炉灶重写。

## 约定（先读）

- `<skill_dir>` = 本 SKILL.md 所在目录（含 `scripts/check_brief.py`、`assets/brief_template.md`）。
- 运行时产物一律放**当前会话工作目录**：草稿 `temp/brief_draft.md`、终稿 `output/brief_final.md`（目录不存在先建）。**不要写进 skill 目录**。
- 需要 Python。命令依次试 `python`、`py -3`。
- 简报硬结构（检查脚本按此判定，别改标题措辞）：
  `# 标题`（恰一个）→ 标题下可放一段 `> 核心发现` 引言 → `## 摘要` → `## 背景` → `## 分析` → `## 建议` → `## 数据与引文溯源清单`。正文只用一级/二级标题，**不出现 `###`**。
- 字数口径与脚本一致：正文（不含溯源清单）默认 1500–2500 字；中文/全角标点每字 1，连续英文/数字串每条 1。用户有特殊篇幅要求就改 `--min/--max`。
- 引用规范：凡数据/条文论断，句尾打 `〔#ID〕`；溯源清单为每个 ID 起一行 `| #ID | 文中说法 | 出处 | 状态 |`。
- 事实分工：**脚本查不了真伪**。机械项归脚本（结构/篇幅/引用标注/术语/占位符），事实归**第 4 步溯源核对**（对照用户提供的原文逐条核实）。给不了原文时，全文状态只能标"待核"，并明确告诉用户这是未核对的初稿。

## 第 0 步：解析任务

1. 收齐输入：{主题} + {源材料文件路径}（政策文件/研究报告等，可多个）。源材料缺失 → 问用户要；用户坚持没有 → 照常走流程但**在第 4 步所有行标"待核"**并提示。
2. 确认受众/篇幅口径（默认中文决策者、1500–2500 字），有特殊要求记录给第 2 步 `--min/--max`。

## 第 1 步：生成初稿

1. 读 `<skill_dir>/assets/brief_template.md`，按它的结构与规范成文。
2. 通读源材料，提炼四板块内容；**每个数字/条文论断都从材料里来**，并就近打 `〔#ID〕`。
3. 成稿写入 `temp/brief_draft.md`，删掉模板里的使用说明与示例占位。

## 第 2 步：机械检查

```bash
python "<skill_dir>/scripts/check_brief.py" --input temp/brief_draft.md [--min M --max M] [--terms '规范名=异体']
```

读输出里的 FAIL/WARN 行。**只有这一脚本说的机械问题按它改**；它报通过 ≠ 事实没问题（事实留给第 4 步）。

## 第 3 步：精修循环（最多 3 轮）

1. 逐条修掉上一轮脚本报的 FAIL（改 `temp/brief_draft.md`，不是另写新文件）。
2. 重跑第 2 步命令，看是否全过。
3. 没过就重复，**轮数上限 3**。到第 3 轮仍有未通过项 → **停下来**，把剩余问题清单连同草稿给用户，绝不静默交付一份没过检的简报。Why：这技能的全部意义就是让输出过门槛；差几项硬过等于没用。

## 第 4 步：事实溯源核对

脚本通过后，做**逐条溯源**（这是"事实准确性"唯一的落地方式）：
- 打开用户给的源材料，逐行核对溯源清单：说法与原文的**数字、条款、日期、口径**一致 → 状态改 `✓ 已核对`；在原文里找不到/无法确认 → 保持或改 `待核`。
- **不为了"好看"改数据去迁就结论**，也不把核对不上的一句删掉当没发生。核对不上的，保留原句但标 `待核`，最后向用户点出。

## 第 5 步：定稿

1. 应用最终格式：标题下加三句话「核心发现」引言块（每句一句判断，不夹带未核对事实）；清理残留说明文字；确认无 `###`、无占位符。
2. 存 `output/brief_final.md`，把路径 + 溯源清单里 `待核` 条数（及其 ID/内容）汇报给用户。

## 收尾自查

- `temp/brief_draft.md` 与 `output/brief_final.md` 都在；检查脚本对终稿再跑一次应**全部通过**。
- 四板块依序、只有两级标题、无占位符。
- 每个 `〔#ID〕` 在溯源清单有行；每个含量词的数据句都有标记。
- 溯源清单状态齐全：已核对 的确实与原文一致；`待核` 的已单独报给用户。
- 没有把相关性/单一来源当定论。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| `python` 不存在 | 试 `py -3`；都没有就告诉用户装 Python 或用其现有解释器路径 |
| 脚本报"超出允许范围" | 加/删实质内容（不是注水），改完重跑；或用户确认改 --min/--max |
| 报"缺 `〔#ID〕`" | 找到那行数据句补出处标记，并在溯源清单补对应行 |
| 溯源清单行未在正文引用 | 删该行，或回正文补引用 |
| 原文核对不上某条 | 状态标 `待核`，上报用户；不要删改数据造假 |
| 用户临时要别的板块结构 | 说明结构与脚本校验绑定；确要改则连同 `--` 参数与模板一起调整 |
