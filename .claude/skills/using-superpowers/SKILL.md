只要你觉得某个技能有哪怕 1% 的可能适用于手头的事，就绝对必须调用它。

只要某个技能适用于你的任务，你就没有选择，必须用它。

这没得商量。你没法靠找理由绕过去。
</EXTREMELY-IMPORTANT>

## 规则

**在做出任何回应或动作之前，先调用相关或被点名的技能** —— 包括澄清问题、翻代码库、查文件。如果用了之后发现不适用于当前情况，你不必继续用它。

**进入 plan 模式之前：** 如果还没做过头脑风暴，先调用 brainstorming 技能。

然后声明一句“正在用 [技能] 来实现 [目的]”，并严格照技能执行。如果技能里有检查清单，就为每一项建一条待办。

## 技能优先级

多个技能都适用时，流程类技能优先 —— 它们定方向，再由实现类技能（frontend-design 等）去落地。brainstorming 和 systematic-debugging 是 Superpowers 里最常用的流程类技能，但这条规则对任何流程类技能都成立。

- “我们来做个 X” → 先用 superpowers:brainstorming，再用实现类技能。
- “修一下这个 bug” → 先用 superpowers:systematic-debugging，再用领域技能。

## 危险信号

冒出下面这些念头就说明该停下 —— 你在给自己找理由：

| 念头 | 现实 |
|---------|---------|
| 「这只是个简单的问题」 | 问题也是任务。先查有没有对应技能。 |
| 「我得先多了解点背景」 | 查技能要在澄清问题之前。 |
| 「先把代码库翻一遍」 | 技能会告诉你该怎么翻。先查技能。 |
| 「我快速看下 git / 文件就行」 | 文件里没有对话的来龙去脉。先查有没有技能。 |
| 「先收集点信息」 | 技能会告诉你该怎么收集信息。 |
| 「这用不着走正式技能」 | 只要有技能，就用。 |
| 「这技能我记得」 | 技能会更新。读当前版本。 |
| 「这不算个任务」 | 有动作就是任务。先查技能。 |
| 「用技能太小题大做了」 | 简单的事会变复杂。还是用。 |
| 「我先把这一件事做了再说」 | 做什么之前都先查。 |
| 「这样做感觉挺有产出」 | 没章法的动作只会浪费时间。技能就是为了防这个。 |
| 「我知道那是什么意思」 | 懂概念不等于用了技能。调用它。 |
