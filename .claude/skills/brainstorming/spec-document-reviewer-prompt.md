# 规格文档审阅者提示词模板

派发规格文档审阅 subagent 时，用这个模板。

**目的：** 核查规格是否完整、前后一致、可以拿去写实现计划。

**派发时机：** 规格文档写入 docs/superpowers/specs/ 之后。

```
Subagent (general-purpose):
  description: "Review spec document"
  prompt: |
    你是一名规格文档审阅者。核查这份规格是否完整、可以拿去写计划。

    **要审的规格：** [SPEC_FILE_PATH]

    ## 要检查什么

    | 类别 | 要找的问题 |
    |----------|------------------|
    | 完整性 | TODO、占位符、“TBD”、没写完的章节 |
    | 一致性 | 内部自相矛盾、需求互相冲突 |
    | 清晰度 | 需求含糊到会让人做出错的东西 |
    | 范围 | 是否够聚焦，能撑起一份计划 —— 而不是覆盖多个彼此独立的子系统 |
    | YAGNI | 没要求过的功能、过度设计 |

    ## 尺度把握

    **只报那些真正会在写计划时造成麻烦的问题。**
    缺了一节、前后矛盾、某条需求含糊到能被理解成两种意思 —— 这些算问题。
    措辞上的小改进、文风偏好、“某节没别节写得细”都不算。

    除非有严重到会导致计划跑偏的缺口，否则就批准。

    ## 输出格式

    ## 规格审阅

    **状态：** 批准 | 发现问题

    **问题（如有）：**
    - [第 X 节]：[具体问题] - [为什么它会影响写计划]

    **建议（仅供参考，不拦批准）：**
    - [改进建议]
```

**审阅者返回：** 状态、问题（如有）、建议
