# A股季度财报分析（顺序工作流）

本 skill 把「上市公司财报分析」编排成一条确定性的顺序流水线。**每一步都要有产出物，且下一步只消费上一步的产物**——不要跳步，也不要在第 3 步才想起第 1 步的数据。

目标报告期 `YYYY-MM-DD`（2026-03-31=一季报 / 06-30=中报 / 09-30=三季报 / 12-31=年报），文件以 `{6位代码}_{YYYY-MM-DD}` 命名，例如 `data/ratios_600519_2026-06-30.json`、`output/report_600519_2026-06-30.md`。

## 约定（先读）

- `<skill_dir>` = 本 SKILL.md 所在目录（含 `scripts/`、`references/`、`assets/`）。运行时产物一律放在**当前会话工作目录**下的 `data/` 与 `output/`，不要写进 skill 目录。
- 数据金额单位是**元**（源口径）；写报告时换算成 **亿元**（÷1e8，保留 2 位）。
- `data/`、`output/` 不存在就先创建。
- 需要 Python + akshare(≥1.14)。若 `python` 不在 PATH，依次试 `py -3`。
- 本 skill 面向**非金融**上市公司。银行/券商/保险/租赁等金融业的资产负债表结构与"流动比率"等口径不适用，遇到请先向用户说明并征询是否仍要继续。

---

## 第 0 步：解析任务

1. 从用户的话里提取 **{代码/简称}** 与 **目标报告期**。代码可能是 `600519`、`SH600519` 或"贵州茅台"。
2. 目标报告期没给时，默认取**最新已披露**的一期（脚本会自动判定），并向用户确认一句即可，不必追问。
3. 明确**行业/可比口径**：先看 `data/raw/{code}/meta.json` 里的 `industry_em`；若为空，向用户确认公司所属**申万一级行业**（基准表表头/第 3 步要据此对照），供第 3 步用。
4. **缓存**：只要 `data/raw/{code}/` 已有且报告期一致，第 1 步脚本会自动复用，不用重抓。

## 第 1 步：抓取三大报表

```bash
python "<skill_dir>/scripts/fetch_statements.py" --ticker {代码或简称} [--report-date YYYY-MM-DD] [--workdir .]
```

产出：`data/raw/{code}/` 下的 5 张表 + `meta.json`（利润表/资产负债表/现金流量表，均分"按报告期=累计"与"按单季度"两套）。

**做（Why：联网取数源经常变动，脚本只负责把数抓下来变成干净结构，校验与解读是你的事）：**
- 跑完**检查产出**：每张表都应有"ok N 期"；`meta.json` 里 `target_report_date` 等于你要的分析期。
- 抓取失败时读脚本给的提示（多为 akshare 版本过旧/网络问题），`--refresh` 可绕过缓存强刷。

## 第 2 步：计算核心比率

```bash
python "<skill_dir>/scripts/compute_ratios.py" --ticker {代码} [--report-date YYYY-MM-DD] [--workdir .]
```

产出：`data/ratios_{code}_{YYYY-MM-DD}.json`，内含 `cumulative`（年初至今累计）、`single_quarter`（单季）、`ttm`、`metrics`（每个都带 `basis`+`definition`）、`for_peer_compare`（已按规则选好和行业对比用哪套数）。

**做（Why：比率是后续所有论断的根基，错一个数整个报告就废）：**
- **逐条核对口径再往下走**。最常错的是把"单季"当"累计"、把"含少数股东净利润"当"归母净利润"。每个指标照抄 JSON 里的 `definition`/`basis` 成文。
- 用常识做 sanity check：毛利率/净利率应在 0~100%（茅台这类高端消费可 90%+）；资产负债率 0~100%；流动比率应 >0；营收/利润同比若出现 ±1000% 这种值要警惕并复核。
- 本期出现资产减值/公允价值变动等一次性项目时，比率会失真，报告中要主动说明。

## 第 3 步：与行业基准逐项对比

1. 读取 `<skill_dir>/references/industry_benchmarks.md`，找到公司所在行业的表（行业按**申万一级**列示，如食品饮料/电力设备/电子）。公司行业归属若第 0 步没确认，用其申万一级行业。
2. 用 `for_peer_compare` 里的值逐项对比：`current_ratio` / `debt_ratio` / `gross_margin` / `net_margin` / `roe`。
3. 逐项算出与行业中位数的**绝对差距**与**相对位置**（高于/低于/接近，接近定义为差距 < 10%）。
4. 判断"高好还是低好"时**分清指标性质**：毛利率/净利率/ROE/流动比率越高越好；**资产负债率并非越低或越高就好**，要看行业与商业模式，报告中只陈述"高于/低于中位数 X 个百分点"并给一句经营含义，不要简单贴"优于/劣于"标签。
5. 口径一致性（Why：行业基准通常按**最近完整年度**列示，公司若是中报，直接拿半年累计比全年中位数没有意义）：
   - 目标期是**年报** → 直接比；
   - 是**季报/中报** → 优先用 `ttm` 或 `roe_last_fy`（JSON 里已给）；
   - 实在没有可比口径，就**如实注明"行业按年度、公司按累计，仅参考"**，绝不用别的公司的数凑。
6. 基准文件里找不到该行业，或目标公司属于金融业 → **停下来告诉用户**，请其提供基准或选择是否继续，绝不自己编一个中位数。需要的行业不在表内时，可运行 `python "<skill_dir>/scripts/build_industry_benchmarks.py" --industries {申万一级代码}` 联网补算（需新浪/申万/东财业绩报表接口可达），或由用户给出权威基准。
7. 把对比结果写成 `data/compare_{code}_{date}.json`（每项含指标、公司值、口径、行业中位数、差距、位置），并在报告同业对比处注明基准来源与样本口径（见基准表表头）。

## 第 4 步：按模板产出报告

1. 读取 `<skill_dir>/assets/report_template.md`，按其**四段结构**成文：①数据摘要 ②比率分析 ③同业对比 ④风险提示。
2. 数据来源写"公司定期报告，经东财(EM)接口获取（akshare）"，**不要**写成"已核实/审计"。
3. 金额换算亿元；比率带上 `basis` 口径（如"累计""单季""TTM"）。
4. 同业对比处**引用 compare JSON 的数字**，不能改数。基准来自 `references/industry_benchmarks.md`（申万一级、按公开定期报告自算中位数），在报告同业对比/说明处注明基准来源与样本口径，不要把自算中位数说成第三方官方统计。
5. 写入 `output/report_{code}_{date}.md`，并把文件路径汇报给用户。

## 全流程收尾自查

- 三份中间产物齐全：`data/raw/`、`data/ratios_*`、`data/compare_*`。
- 报告里所有同比/环比数字与 JSON 一致，口径标签（累计/单季/TTM/期末）正确。
- 没有编造行业中位数；基准不确定处都如实标注。
- 无一次性因素未披露、无单位错误（元↔亿元）。
- 银行等金融股若误入，已向用户说明。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| `akshare 中不存在函数 stock_*_by_*_em` | 版本过旧：`pip install -U akshare` 后 `--refresh` 重抓 |
| 行业取不到 | meta 里 `industry_em` 为空属正常，直接问用户 |
| 目标报告期数据缺失（如新股、停牌） | 换最近一期并告知用户 |
| 负数净资产/营收为零 | 比率会异常，删除该项并在报告中说明原因 |
| 需要更多报表科目 | 只存了常用科目；临时补抓可用 akshare 原函数，别改存档格式 |
