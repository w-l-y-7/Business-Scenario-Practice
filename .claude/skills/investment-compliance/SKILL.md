# 投资交易合规检查

把一笔/一批交易按监管规则与风控标准逐项过一遍，产出**可复核的审计报告**；高风险或证据不足时判"待复核"，**标记人工审核，不自动放行**。

## 约定（先读）

- `<skill_dir>` = 本 SKILL.md 所在目录。规则清单在 `references/regulatory_rules.md`，**每次开工先读一遍**——规则可能更新，不靠记忆。
- 交易信息来自用户给的**文件**（JSON/CSV）或**对话描述**；两者都没有，先问清：金额、方向、资产类别、对手方、以及可作证据的材料。
- 产物写到**当前会话工作目录**下 `output/compliance_{date}_{id}.md`（目录不存在先建），不要写进 skill 目录。
- 本技能产出的是**风险判定与审计记录**，不是法律/合规免责保证；涉及真实放行的结论需合规岗最终签核。

## 证据式制裁筛查（关键口径）

本机没有活的 OFAC/EU/UN 名单源，**绝不内置一份会过期的名单快照来假装"已核对"**。

- 对手方是否命中制裁/黑名单，只能靠**权威来源的核对证据**（官方名单查询结果/核验单号、银行或合规系统留痕）。
- **没有证据 → 该项判"待复核"**。禁止"没查到=干净"式的默认通过。
- 用户给的证据要如实记录来源与时间；来源不权威或已过期 → 标注并降级为待复核。

## 步骤 1：获取交易信息

对每笔交易整理：金额、方向（买/卖）、资产类别、对手方名称与类型、集中度所需持仓/净值数据、是否有制裁核对证据。

**做（Why：规则判定全依赖输入质量，字段缺失先问或标 NA，不要猜）：**
- 多笔输入**逐笔处理、逐笔给结论**，别混成一坨。
- 需要集中度判定但没给净值/总资产 → 该项标"待补数据"，**不能默认不超限**。
- 交易信息与对话里已知事实冲突 → 以用户书面输入为准并指出冲突。

## 步骤 2：逐项应用规则

读 `references/regulatory_rules.md`，按 A→E 逐项核对，对每项记录：检查内容、依据、命中与否、所需证据是否到位。

- 制裁筛查（A）严格走上面的证据式口径。
- 集中度（B）：单一标的敞口 / 基金净值，对照阈值；缺净值就标待补数据。
- 关联交易（C）：对手方与你掌握的关联清单比对；对不上但存疑（名称/股权线索）→ 标"疑似关联，待人工确认"，**不自己拍板是或否**。

## 步骤 3：风险定级

逐笔按以下触发定级，**存在任一高危触发即取最高档**：

| 风险 | 触发条件 |
| --- | --- |
| 低 | 金额 < 50 万 且 对手方为白名单机构 且 制裁核对证据通过 |
| 中 | 金额 50–500 万；或首次交易对手方 |
| 高 | 金额 > 500 万；或涉及高风险地区/禁投清单；或关联交易；或制裁核对待复核 |

白名单/关联标记应由用户或合规数据给出，不是本技能自己认。

## 步骤 4：输出审计报告

报告含：交易概览 / 逐项筛查结果表 / 风险等级与依据 / 合规结论 / 复核与证据要求。

- 合规结论三态：**通过 / 待复核 / 不通过**。高风险或证据不足 → 待复核并标"需人工审核，不自动放行"。
- **逐笔**都要写清：命中了什么、证据状态、结论与理由，别让读者猜。
- 保存 `output/compliance_{date}_{id}.md`，并在对话里给要点摘要（不是复读全文）。

## 收尾自查

- 每笔交易都有独立结论（通过/待复核/不通过）+ 理由。
- 制裁筛查没有无证据的"通过"；证据来源与时间都写进报告。
- 高风险与证据不足的都标了"需人工审核"。
- 报告在 `output/`，每个数字/判定能溯源到输入或规则条款。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 用户只给了股票代码和金额，说"查合规" | 先问方向、对手方、净值/持仓；材料不够就按现有信息出"待补数据"的待复核报告 |
| 对手方名字看起来很生僻/境外 | 制裁项只能给"待复核，需权威核对"，不因拼写生僻判通过 |
| 集中度差一点超（9% vs 10%） | 如实报比例与对照值；是否预警看机构内规，报告里给结论待人工确认 |
| 用户说"我查过了没事" | 记录其口头主张但标注"无书面证据"，该项仍按待复核处理 |
| 一批里有 3 笔正常 1 笔高危 | 逐笔报结论，高危那笔单独标"需人工审核"，不拖正常笔下水 |
