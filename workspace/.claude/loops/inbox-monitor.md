# inbox 监控（每天一次）

**干什么**：每天固定扫一遍 `inbox/`，把**带便签**的文件拾取成任务，按便签指定的 skill 处理完。便签是唯一入口——没有便签的文件一律不动。

**怎么触发**：把下面「循环指令」喂给 /loop（`/loop 1d <指令>`），每天跑一次。

## 循环指令（可直接喂给 /loop）

> 打开 `workspace/.claude/loops/inbox-monitor.md`，照里面的步骤跑一遍。

## 步骤

1. 列出 `inbox/` 里的所有文件，挑出便签 `task-*.md`。
2. **没有便签 → 静默结束**：一个 `task-*.md` 都没有就直接停，不输出任何内容、不做多余动作（没有新文件时同理）。
3. 逐个便签处理，一张便签一个任务：
   1. 按便签内容建 `tasks/{YYYY-MM-DD}-{任务名}/`，日期取当天，任务名用便签里已定的中文简称。
   2. 把便签和它对应的**源文件**一起从 `inbox/` 移进任务文件夹。
   3. 按便签指定的 skill 处理，产出物存同一任务文件夹，文件名体现内容（别用 output.xlsx 这类通用名）。
   4. 按 [rules/task-changelog.md](../rules/task-changelog.md) 更新 `changelog.md`、`daily/{YYYY-MM-DD}.md`、`tasks/README.md`。
4. **没带便签的文件一律跳过**：不建任务、不移动、不记录。
5. 收尾汇报：处理的每个任务一句话说清建了哪个文件夹、产出什么；被跳过的文件不逐个报，只提一句总数。

## 异常处理

单个任务失败只影响这一个任务，不要中断整轮：

1. 把该任务的**源文件和便签移回 `inbox/`**，已建的任务文件夹一并清掉，让 inbox 回到原样、下一轮能重来。
2. 在 `changelog.md` 追加一行，备注写「失败」+ 错误原因。
3. 便签里写的源文件在 `inbox/` 找不到 → 同样把便签移回 `inbox/`，`changelog.md` 记一行说明。
4. 记完接着处理剩下的便签。

## 停止条件

用户说「停」就停。
